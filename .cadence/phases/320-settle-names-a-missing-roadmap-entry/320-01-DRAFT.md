# 320-01 — settle names a missing roadmap entry

## Objective

Stop `.cadence/ROADMAP.md` and `.cadence/MILESTONES.md` from silently falling behind settled phases (rec-20261004-001). Today no step of the loop — no code on the draft/build/settle path and no skill checklist — reads or writes either file; the only detector, `cadence doctor`'s `roadmap-currency` check (phase 259), is warn-only, runs only when doctor is invoked, and keys on a 10-phase max-drift that cannot see in-range gaps. The files have been hand-backfilled at least four times (PR #321, PR #523, phase 303's inline patch, plus open recs for 239–241 and 271–280), and on `main` at `ec706481` the newest `### Phase` heading is 313 while phase directories reach 319. Phase 259 records that roadmap prose must never be auto-generated, so this phase adds detection at the moment it can still be acted on rather than generation: a best-effort, non-blocking stderr notice at successful settle naming the settled phase's missing entries (per phase, not per drift), checklist lines in the `phase-build` and `release-cut` skills, a one-off backfill of phases 314 and 316–320 plus the stale `(in progress)` markers on 292 and 303, and a repo record-integrity test that requires both entries for every on-disk phase numbered 314 or higher so CI catches the next miss in this repo.

## Acceptance Criteria

### AC-1: pure per-phase entry check
Given a phase number N, the text of ROADMAP.md (or null when the file is absent), and the text of MILESTONES.md (or null when absent)
When the pure check runs
Then it reports ROADMAP.md as missing when that text contains at least one `### Phase <digits>` heading but none whose number equals N exactly (so a `### Phase 32` heading never satisfies N = 320 and `### Phase 320` never satisfies N = 32), reports MILESTONES.md as missing under the same rule for its `- **Phase <digits>**` bullet convention, and reports nothing for a file that is null or contains zero headings of its convention (the `cadence init` stub, or a project that does not use the convention)

### AC-2: successful settle prints a notice naming each missing file
Given a repository whose ROADMAP.md uses `### Phase N` headings and whose MILESTONES.md uses `- **Phase N**` bullets, neither containing an entry for the phase being settled
When `cadence settle run` succeeds for that phase
Then stderr carries one notice naming the phase number, each missing file, and the expected heading/bullet form, and saying roadmap prose is never auto-generated; stdout carries no roadmap line; settle exits 0; `SUMMARY.json` gains no roadmap-related field; and both roadmap files are byte-identical before and after the settle

### AC-3: the notice is silent when not applicable and never fails settle
Given a successful settle where both files already carry the settled phase's entry, or where either file is absent or uses no phase convention, or where reading either file throws
When `cadence settle run` succeeds
Then the notice names no file that is present-and-current, absent, convention-free, or unreadable — each file is judged on its own, so an unreadable ROADMAP.md does not suppress a genuinely missing MILESTONES.md entry — no notice is printed when no file qualifies, settle still exits 0, and a refused settle never prints the notice

### AC-4: the build and release checklists name the roadmap entries
Given `.claude/skills/phase-build/SKILL.md` step 7 (settle, one commit) and `.claude/skills/release-cut/SKILL.md` step 3 (doc-sync verification)
When an agent follows either step
Then phase-build step 7 lists adding the phase's `### Phase N` entry to `.cadence/ROADMAP.md` and its `- **Phase N**` bullet to `.cadence/MILESTONES.md` (in final form, no `(in progress)` marker) among the things staged in the single settle commit, release-cut step 3 tells the operator to confirm every phase in the release has both entries and none still says `(in progress)`, and `packages/core/tests/docs/roadmap-entry-checklist.test.ts` asserts both statements

### AC-5: this repository's records are current and stay current
Given `.cadence/ROADMAP.md`, `.cadence/MILESTONES.md`, and the numbered directories under `.cadence/phases/`
When `packages/core/tests/docs/roadmap-per-phase-entries.test.ts` runs
Then every on-disk phase directory numbered 314 or higher has both a `### Phase N` ROADMAP heading and a `- **Phase N**` MILESTONES bullet (phases 314 and 316–320 are backfilled from their merge commits and DRAFT/SUMMARY files; 315 has no directory and is not required), and the `### Phase 292` and `### Phase 303` headings no longer say `(in progress)` and carry their PR numbers (#469, #496) with an `As built` line
