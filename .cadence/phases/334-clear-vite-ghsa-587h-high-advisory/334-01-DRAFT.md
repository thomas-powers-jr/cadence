# 334-01 — Clear the vite GHSA-587h high advisory with override floors

## Objective

Clear GHSA-587h-7wmj-h5pm (high, published 2026-10-20T19:48Z), which since 2026-10-21 fails `security-success` on every PR because `scripts/check-audit-exceptions.mjs` reports `FAIL GHSA-587h-7wmj-h5pm (vite, high) — not listed in docs/security/audit-exceptions.md` (run 39613760385). Re-measured 2026-10-21 in this worktree, `pnpm audit` on the root reports 3 advisories, all against the dev-only vite 7.3.6 that vitest pulls in as a peer: GHSA-587h-7wmj-h5pm (high) plus GHSA-698v-4r3x-3vcv and GHSA-r825-w8mm-5pxw (moderate), each `>=7.0.0 <=7.3.6`, patched `>=7.3.7`. The advisory also names launch-editor `<=2.14.1` (patched 2.14.2); `pnpm why launch-editor -r` shows it resolved at 2.14.2 under `@changesets/cli`, already patched. Fix it the phase 330 way, with durable caret `pnpm.overrides` floors in the private root `package.json`: raise the existing `vite@^6.0.0 || ^7.0.0 || ^8.0.0` target from `^7.3.5` to `^7.3.7`, and add `launch-editor@<2.14.2: ^2.14.2` so a future lockfile refresh cannot drift back below the patched line. The vite change raises the existing key in place rather than adding the separate `vite@<7.3.7` key the request named. That existing selector is what holds vite on the 7.x line for vitest's `^6 || ^7 || ^8` peer, a second overlapping vite key would leave the result to pnpm's precedence between same-name keys, and keeping the old `^7.3.5` target would let a plain `pnpm install` keep the locked 7.3.6. This mirrors phase 330, which raised the ip-address target and moved the fast-uri key rather than stacking keys. Run `pnpm install`, not `pnpm update`. vite stays on 7.x: adopting vite 8 or vitest 5 is out of scope.

The root fix alone does not turn `security-success` green. The security workflow's audit job runs the same check against `website/`'s own lockfile in a later step, which run 39613760385 never reached because the root step failed first. Measured 2026-10-21, that step fails too: GHSA-gfr2-rv44-r23c (markdown-it, high, published 2026-10-20T20:28Z, `>=14.1.0 <14.3.3`, patched `>=14.3.3`) against markdown-it 14.3.2, which reaches the docs site only through the website's direct `typedoc` devDependency (0.28.20, `markdown-it: ^14.3.0`), which starlight-typedoc also peers. The same bump clears the low GHSA-vfgh-jcmw-g37q against the same package. A root-only PR and a website-only PR would each fail `security-success` on the other's advisory, so both legs land in this one phase. The website leg follows phase 328: a line-scoped caret floor `markdown-it@^14.0.0: ^14.3.3` in the private `website/package.json` `pnpm.overrides`, then `pnpm install` in `website/`. The key is scoped to the 14.x line so no other major can be pulled across lines. The remaining website moderate, GHSA-rj75-hqrm-r3gf against postcss-selector-parser 6.1.4, is below the gate's high/critical threshold. Its patch is the 7.x major, so it stays out of scope. Neither the root nor the website manifest is published, and no published `packages/*/package.json` changes, so there is no changeset.

> **As built (2026-10-21).**
> - **T2's plain `pnpm install` did not move vite.** It rewrote the overridden peer specifiers in `pnpm-lock.yaml` (`vite: ^7.3.5` → `^7.3.7` under vitest and @vitest/mocker), but kept the locked vite at 7.3.6 and warned `unmet peer vite@^7.3.7: found 7.3.6`. pnpm 9.12 reuses a locked auto-installed peer even when the overridden range no longer admits it. `pnpm install --fix-lockfile` did the same.
> - **Boundary deviation, attempted and fully reverted.** `pnpm update vite -r --depth Infinity` was run against the last Boundaries line. It churned 231 unrelated lockfile lines and still left 7.3.6. Both files were restored from a byte-for-byte backup taken just before, and nothing from it remains in the diff.
> - **Out-of-prescription step.** What worked was deleting only the two stale `vite@7.3.6` blocks (its `packages:` entry and its `snapshots:` entry) from `pnpm-lock.yaml` by hand, then re-running `pnpm install`, which re-resolved vite to 7.3.7. The resulting diff touches only vite: the importer and snapshot peer suffixes, its integrity hash (it matches `npm view vite@7.3.7 dist.integrity`), the two peer-spec lines and the override header. vite 7.3.7's own dependency set is unchanged. `pnpm install --frozen-lockfile` accepts the result.
> - **Windows `corepack` limit.** On this Windows dev box, `node scripts/check-audit-exceptions.mjs` cannot spawn `corepack` (`spawnSync corepack ENOENT`; `shell: false` does not resolve `corepack.cmd`). That is a local environment limit, and Linux CI is canonical. Locally, the unmodified script was run with a scratchpad `--import` preload that sets `shell: true` for that one spawn. It exits 0 on the root and reproduces CI's exact `FAIL GHSA-587h-7wmj-h5pm (vite, high)` on `origin/main`'s package.json and lockfile.
> - **AC-4 and T3 were added after approval.** The independent review found the website markdown-it high described in the Objective's second paragraph. The Objective, AC-3's title and the website boundary were amended to match.
