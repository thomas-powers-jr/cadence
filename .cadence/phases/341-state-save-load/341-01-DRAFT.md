# 341-01 — cadence state save | load | list carries loop state between machines through committed snapshots

## Objective

`.cadence/state.json` is gitignored, so the live loop position does not travel with a branch. Moving work to another machine mid-loop loses it. Cadence Studio built its own `pnpm cadence-state save | load | list` (Studio's `scripts/lib/cadence-state.ts`) to carry a committed snapshot between PCs. This phase moves that capability into core as `cadence state save | load | list`, following dec-20261029-001 and the operator's choices:
- **Snapshot directory:** snapshots go in a dedicated, committed `.cadence/snapshots/`, not in `.cadence/handoff/`.
- **Retention:** `save` prunes the directory to the newest 3 snapshots.
- **Restore is its own command.** `cadence resume` stays read-only (D10, LOCKED).
- **On load, session-local counters reset and progress is kept:**
  - reset: `session.tokenUtilization`, `session.subagentSpawns`, `session.subagentBaselines`;
  - kept: everything else, including `skillAudit.invoked`, `activeTask`, `draftReadAt` and `draftReadHash`.
- **`revision` moves past both sides:** the restored state's `revision` becomes `max(local, snapshot) + 1`. A process on this machine still holding the old state then hits the existing concurrent-write refusal.

A snapshot is a committed file, so it can arrive from anyone through a branch or PR, and load treats it as untrusted input. Every path-bearing field is validated before anything touches the filesystem.

Machine-local bookkeeping lives in one new gitignored directory, `.cadence/local/`. It holds:
- **`state.json.bak`:** the state a load replaced;
- **`state-sync.json`:** the local `revision` right after this machine's last save or load.

Load refuses (unless `--force`) only when this machine has provably changed since its last save or load, that is, when the local `revision` is past the sync marker. Raw `revision` values from two machines are never compared, because each checkout bumps its own counter on every hook and command.

Phase 340's content-hash `draft-read` gate is what makes a mid-BUILD restore settle cleanly, so a mid-loop load needs no special flag. It only warns when the snapshot predates `draftReadHash`.

## Acceptance Criteria

### AC-1: save writes a committed, named snapshot and prunes to the newest 3
Given a repo whose `.cadence/state.json` parses through `CadenceStateZ`
When `cadence state save` runs
Then:
- **Location and name:** it writes `.cadence/snapshots/state-<stamp>-<host>.json`:
  - `<stamp>` is the UTC time to the second with no colons, e.g. `2026-10-29T231502Z`;
  - `<host>` is `os.hostname()` with every character outside `[A-Za-z0-9-]` replaced by `-`, cut to 40 characters, and `unknown-host` when that leaves an empty string.
- **Content:** the file holds `{ "snapshotVersion": 1, "savedAt": <ISO8601>, "host": <sanitized host>, "cadenceVersion": <running core version>, "state": <the CadenceStateZ-parsed state.json> }`.
- **No overwrite:** if a file with that exact name already exists, save refuses with exit 1 and overwrites nothing.
- **Pruning:** afterwards `.cadence/snapshots/` holds at most 3 `state-*.json` files: the one just written, plus the newest others by name. Each pruned file is named on stderr. Files not matching `state-*.json` are never touched.
- **Sync marker:** `.cadence/local/state-sync.json` records `{ "revision": <local revision> }`.
- **Handoff warning:** when `state.session.lastHandoff` is `null`, stderr warns that no handoff is linked.
- **Missing or unparseable state:** save refuses with exit 1 and writes nothing.
- **Output:** stdout names the written file and the saved loop position. With `--json`, stdout is exactly one JSON object: `{ path, position: { loop, phase, draft }, pruned: string[], warnings: string[] }`.

### AC-2: list shows snapshots newest first
Given `.cadence/snapshots/` with zero or more files
When `cadence state list` runs
Then:
- it prints one line per `state-*.json`, newest first, each with the file name, `savedAt`, `host` and loop position;
- a file that fails to parse as a snapshot is still listed, marked unreadable, with a stderr warning, and the command still exits 0;
- an absent or empty directory prints a clear "no snapshots" message and exits 0;
- `--json` prints exactly one JSON array of `{ name, savedAt, host, position }` (unreadable entries carry `error` instead of `savedAt`, `host` and `position`).

### AC-3: load refuses, without touching any file, when the snapshot does not fit
Given a snapshot to load: the newest `state-*.json` by default, or one named by an argument that is either a bare file name inside `.cadence/snapshots/` or a path
When `cadence state load` runs and any of the following holds
Then it exits 1, and under `--json` stdout is empty. Stderr names the problem and the fix. `state.json`, `STATE.md` and everything in `.cadence/local/` are byte-unchanged:
- no snapshot exists, or the named one is not found;
- the file is not valid JSON, or its `snapshotVersion` is not `1`, or its `state` fails `CadenceStateZ`;
- **unsafe paths:** a path-bearing field is not a plain identifier. This is checked before any existence probe, and `--force` never overrides it. The fields are:
  - `activePhase`: must pass `assertSafePhaseSlug`;
  - `activeDraft`, `activeSpec` and `activeTask.id`: must match `/^[A-Za-z0-9][A-Za-z0-9._-]*$/` with no `..`;
  - `session.lastHandoff`: must be a bare `SESSION-*.md` basename;
- **unknown keys:** the snapshot's raw `state` has a top-level key `CadenceStateZ` does not know. Loading would silently drop it, so the message names the key(s) and the snapshot's `cadenceVersion`, and says to update cadence or pass `--force`;
- a parseable local `state.json` exists and its `project.name` differs from the snapshot's;
- the snapshot's `activePhase` is non-null and `.cadence/phases/<activePhase>/` does not exist on this branch. The message says to pull or switch branch;
- **local work since last sync:** `.cadence/local/state-sync.json` exists, and the local `revision` is greater than the revision it records, so this machine has changed since its last save or load. `--force` skips this check only, and stderr says so loudly. The message names both revisions and suggests `cadence state save` first.

### AC-4: a successful load restores progress, resets session counters, and keeps a backup
Given a snapshot that passes every AC-3 check
When `cadence state load` runs
Then:
- **Backup:** if a local `state.json` existed, its exact bytes are written to `.cadence/local/state.json.bak`, replacing any earlier backup. This happens after the plan has passed every check and immediately before the state write.
- **Restored state:** the new `state.json` equals the snapshot's parsed `state`, except:
  - `session.tokenUtilization` is `0`;
  - `session.subagentSpawns` is `0`;
  - `session.subagentBaselines` is `{}`;
  - `revision` is `max(local revision or 0, snapshot revision) + 1`.
- **Kept fields:** every other field round-trips unchanged, including `skillAudit`, `activeTask`, `decisions`, `deferred`, `session.lastHandoff`, `draftReadAt` and `draftReadHash`.
- **STATE.md:** it is re-rendered from the new state in the same operation, with no separate `doctor --fix` step.
- **Sync marker:** `.cadence/local/state-sync.json` records the new `revision`.
- **Unparseable local state:** if the local `state.json` exists but does not parse, load backs up its bytes as above, skips the project and local-work checks, warns loudly on stderr, and restores the snapshot. Recovering from a broken state is a supported use.
- **Mid-loop warning:** when the snapshot's `loopPosition` is not `IDLE` and its `draftReadHash` is `null`, stderr warns that the `draft-read` gate will fall back to the mtime-only check after this checkout, and suggests re-approving the DRAFT.
- **Newer cadence:** when the snapshot's `cadenceVersion` is newer than the running cadence (and no unknown keys forced a refusal), stderr warns.
- **Output:** stdout reports the loaded file, the position before (or "no state.json"), the position after, and the backup path when there is one. `--json` prints exactly one object: `{ from, before, after, backup, warnings }`.
- **Write conflict:** if another writer changes `state.json` between the plan and the write, load exits 1 with the existing state-conflict message, and under `--json` stdout is empty.

### AC-5: machine-local files are gitignored, snapshots are not
Given `cadence init` (or its gitignore step) on a repo
When it writes CADENCE's owned gitignore entries
Then:
- `.cadence/local/` is among them, appended after the existing four;
- no entry ignores `.cadence/snapshots/`;
- `cadence doctor`'s tracked-cadence-owned-paths check covers `.cadence/local/`, like the other entries;
- this repository's own `.gitignore` also lists `.cadence/local/`.

### AC-6: the command and its decisions are documented, and it ships with a changeset
Given the new command
When the operator reads the docs
Then:
- **commands.md:**
  - `docs/reference/commands.md` lists `state` in the `cadence:commands` marker block;
  - it has a `### state` section documenting `save`, `load` and `list` with their flags (`--json`, `load [snapshot]`, `load --force`), the snapshot location and naming, keep-newest-3 pruning, the AC-3 refusals, the AC-4 resets, `.cadence/local/`, and the exit codes;
  - its `doctor` and gitignore passages list `.cadence/local/` with the other cadence-owned paths.
- **concepts.md:** the "State files" section mentions `.cadence/snapshots/` (committed) and `.cadence/local/` (gitignored).
- **DESIGN.md:** it records that `state load` is a separate, explicit, refuse-first command, which keeps D10's "resume never overwrites machine state". It also records that snapshot retention is a constant of 3, dropped rather than deferred as config.

A `.changeset/*.md` in this PR gives `@thomas-powers-jr/cadence-core` and `@thomas-powers-jr/cadence-types` a `minor` bump. A docs test asserts these points and falls back to core's CHANGELOG once the changeset is consumed.

## Boundaries

- DO NOT change `cadence resume` or `cadence handoff`. Restore is not part of resume (D10, LOCKED), and handoff does not auto-save a snapshot in this slice.
- DO NOT add an MCP tool, a slash command, or a host-adapter change for `state`. The CLI is the only surface in this slice.
- DO NOT make retention configurable. `SNAPSHOT_KEEP = 3` is a constant (YAGNI, recorded in DESIGN.md as dropped, not deferred).
- DO NOT gitignore `.cadence/snapshots/`, and never commit anything under `.cadence/local/`. Committing snapshots is the operator's step, alongside a handoff. They are not part of a phase's settle commit.
- DO NOT compare raw `revision` values across machines for staleness. Only the local sync marker decides "local work since last sync".
- DO NOT let `--force` override the unsafe-path refusal.
- DO NOT change `commit()`'s semantics or any existing `StateBackend` caller. `replaceState` is additive.
- DO NOT change the `draft-read` gate or any gate set, tier × profile cell, or gate ordering.
- DO NOT add a runtime dependency. Use `node:os`, `node:fs`, Zod (already a dependency) and the existing atomic-write helpers.
- DO NOT touch the `cadence-studio` repository. Switching Studio to the core command is Studio's own follow-up.
