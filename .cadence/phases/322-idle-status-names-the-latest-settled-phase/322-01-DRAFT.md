# 322-01 — idle status names the latest settled phase

## Objective

Stop `cadence status`, `.cadence/STATE.md`, and the SessionStart hook banner from presenting a stale phase as current (rec-20261004-002). `settle` resets the loop to IDLE but leaves `state.activePhase` set, and `state.json` is per-checkout and gitignored, while phases are built and settled in worktrees. So the primary checkout keeps reporting the last phase settled *in that checkout* as its "phase" / "Active phase". Reproduced on `main` at `ec706481`: all three surfaces said `311-skill-audit-bypass-recorded-in-gatebypasses` while phases 312–319 were merged. `cadence progress`'s recommendation was unaffected, because its next-free phase number comes from phase directories. Without re-tracking `state.json` (#177 stands) and without changing `activePhase`'s semantics or the `--json` contract, an IDLE checkout now labels that field for what it is. Where a fact about the repo is wanted, the IDLE checkout derives the latest **settled** phase best-effort from the committed phase directories. A directory counts as settled only when its `<id>-SUMMARY.json` carries `stateAtSettle`, which only the success path writes (a refused settle also writes a canonical `SUMMARY.json`, without it).

**Scope limit, stated up front:** this phase fixes the three *display* surfaces named above. The raw `activePhase` still flows unchanged into handoff pre-fill (`active_phase:` in `cadence handoff`), `cadence resume`, the MCP surface, and the intelligence context packet — so `cadence handoff` in a primary checkout can still stamp a stale phase. The stranded DRAFT/BUILD case (a checkout told to settle an already-settled phase) and `cadence progress`'s IDLE path ignoring the milestone/recommendation ledgers are also out of scope; all are filed as follow-up recommendations in this phase's commit.

**As built (2026-10-04):** "the MCP surface" above was too broad. The MCP `cadence_status` tool reuses `statusService`, so it gets the relabelled text, and its json now carries `lastSettledPhase` next to the raw `activePhase`. The `cadence://state` resource serves STATE.md, so it is relabelled too. Only the `cadence://state.json` resource, which serves the raw file, still shows the raw value. rec-20261004-007 carries this correction as evidence. **Correction (whole-branch review, 2026-10-04):** "only" overstates it. The MCP `cadence_handoff` tool (`handoffService`) and `cadence_resume` tool (`resumeService`) also carry the raw value, as does `cadence inspect` (`intelligence/render-inspection.ts:40`). rec-20261004-007 carries these as further evidence. Also, where the Objective says "committed phase directories", the finder reads `.cadence/phases/` in the working tree, not git history; AC-5's As-built note records the doc wording.

## Acceptance Criteria

### AC-1: pure + best-effort latest-settled-phase lookup
Given a list of phase directory entries, each with its name and whether it holds a settled SUMMARY (a `*-SUMMARY.json` that parses and has a `stateAtSettle` object)
When the pure selector runs
Then it returns the name of the settled entry with the highest integer phase number (via `phaseNumber()`), breaks ties by the lexicographically greatest name, ignores entries whose name has no phase number or that are not settled, and returns null when none qualify. And given a repository root, the impure finder reads `.cadence/phases/`, examines directories from the highest phase number downward, and stops at the first settled one. It returns null rather than throwing when the directory is missing, a directory is unreadable, or a SUMMARY is malformed, and it never treats a refused SUMMARY (no `stateAtSettle`) as settled.

### AC-2: `cadence status` on an IDLE checkout
Given a checkout whose loop position is IDLE and whose `state.activePhase` names an older phase than the latest settled phase on disk
When `cadence status` runs
Then the rendered text does not print `phase: <activePhase>`. It prints `last settled: <latest settled phase>` when one is found and omits that line when none is. `cadence status --json` keeps `activePhase` exactly as before and adds `lastSettledPhase` (string or null). For every non-IDLE loop position the rendered text and JSON are unchanged apart from the added `lastSettledPhase` key.

**As built (2026-10-04):** "omits that line when none is" is refined. When no settled phase is found but `activePhase` is set, the text prints `last phase in this checkout: <activePhase>` instead, and omits both lines only when both are null. See T2's As-built note.

### AC-3: `.cadence/STATE.md` on an IDLE checkout
Given a state whose loop position is IDLE
When STATE.md is rendered
Then the `**Active phase:**` line reads `(none — loop is IDLE)`, and a following line `**Last phase in this checkout:** <activePhase or (none)>` preserves the old value under an accurate label. For every non-IDLE state, STATE.md renders exactly as before. The renderer stays pure (no I/O).

### AC-4: SessionStart banner on an IDLE checkout
Given a SessionStart hook dispatch for a checkout whose loop position is IDLE
When the banner context payload is built
Then it reads `Active phase: (none — loop is IDLE)` and, when the latest settled phase is found, adds `Latest settled phase: <name>`. The lookup is best-effort: a failure omits that line and never fails the hook. For every non-IDLE state the banner is unchanged.

**As built (2026-10-04):** when the lookup finds nothing (or fails) and `state.activePhase` is set, the banner adds `Last phase in this checkout: <activePhase>` instead of nothing. See T2's As-built note.

### AC-5: docs describe the IDLE display
Given `docs/reference/commands.md`'s `status` section
When an operator reads it
Then it states that on an IDLE checkout the text output shows `last settled:` (derived from committed SUMMARY files with `stateAtSettle`) instead of the checkout-local `activePhase`, and that `--json` keeps `activePhase` and adds `lastSettledPhase`.

**As built (2026-10-04):** "derived from committed SUMMARY files" is corrected to "the `.cadence/phases/` directories in the working tree". `findLatestSettledPhase` reads the filesystem, so an uncommitted settled SUMMARY counts too. commands.md, the changeset and the AC-5 doc test use the working-tree wording.
