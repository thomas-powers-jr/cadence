# 349-01 — Skill-audit names unobserved host hooks

## Objective

When skill invocations cannot be observed because the host hooks never fired (rec-20261117-001's real cause: a cloud session started in `/home/user`, the parent of the repo, so Claude Code never loaded the repo's committed `.claude/settings.json`, whose hook commands are also cwd-relative; live evidence 2026-11-22: `skillAudit.invoked: []` and `session.tokenUtilization: 0` after several prompts, while the same shim fed a `Skill` payload by hand recorded `phase-build` correctly), CADENCE says so out loud at three points — when a task is recorded, in `cadence doctor`, and in the settle skill-audit refusal, dry-run refusal and bypass reason — instead of producing a plain "required skill(s) not invoked" miss that reads as if the agent skipped the skill; the skill-audit requirement itself, its refuse outcome, and `--allow-skill-audit-miss` are unchanged.

## Acceptance Criteria

### AC-1: Hook events stamp a per-machine liveness time
Given a repository with a `.cadence/state.json`, and a pure `isHookLive(lastHookEventAt, now)` in `packages/core/src/hooks/hook-liveness.ts` that returns true only when the stamp is present, parses as a date, and `0 <= now - stamp <= HOOK_LIVENESS_WINDOW_MS` (a constant of 30 minutes, not config), so a stamp later than `now` is not live
When the hook dispatcher handles any event other than `pre-compact` (that is, every event that reaches `dispatchWithState`, including `session-start`, `user-prompt`, `pre-tool-edit`, `post-tool-edit`, `session-stop`, `subagent-start`, `subagent-result` and `skill-invoke`)
Then, after that event's handler has returned, `state.session.lastHookEventAt` is set to the current time as an ISO-8601 string by a revision-exempt backend write that re-reads `state.json` from disk (as `bumpSessionCounter` does), so a handler's own `commit()` of its earlier in-memory copy cannot overwrite the stamp; the state `revision` is unchanged; the write is skipped when the stamp on disk is live and less than 60 seconds old, and is made when the stamp is later than `now`; the stamp is written whatever the `config.telemetry` settings are; a write failure never fails the hook; `cadence state load` clears `session.lastHookEventAt` on the restored state (a per-machine session fact, reset like `tokenUtilization`); and a `state.json` with no `lastHookEventAt` key (every pre-349 state) still parses, because the field is `.optional()` with no `.default(...)`.

### AC-2: Recording a task without live hooks is flagged on the row and, where hooks are installed, on stderr
Given the loop is in BUILD
When `buildTaskService` (behind `cadence build task`, `cadence done` and the MCP `cadence_build_task` tool) records a task
Then it computes `isHookLive(state.session.lastHookEventAt, now)` from the state it reads before any verifier runs, passes it to `recordTaskOutcome` through `RecordTaskOutcomeOptions`, and the task's PROGRESS.json row carries `hooksObserved: true` or `hooksObserved: false` accordingly (re-recording a task overwrites the earlier value); when it is false and host hooks are installed in the repository (a CADENCE-managed entry in `.claude/settings.json` or `.codex/hooks.json`), this line appears exactly once on stderr: `build task: no host hook event in the last 30 minutes, so skill invocations in this session may not be recorded. Check that the session started in the repository root, where <installed host config path(s)> is loaded.`, naming only the installed config path(s); when no host hooks are installed no line is printed; stdout is byte-identical to today's for the same input; rows written by `cadence block`, `cadence needs-context` and other direct `recordTaskOutcome` callers carry no `hooksObserved` key; and rows written before this phase (no key) still read back.

### AC-3: Settle names the tasks recorded without live hooks
Given settle finds one or more required skills missing from `state.skillAudit.invoked`
When at least one PROGRESS.json task row of the settling draft has `hooksObserved: false`
Then the text `; host hooks were not observed when task(s) <ids> were recorded, so a skill invoked in that session would not have been recorded` is inserted directly after the missing-skill list in the refusal line on stderr (before its `. Invoke them, or pass --allow-skill-audit-miss to override.` tail), in the `settle run --dry-run` refusal reason (the same line, produced once by `runSkillAuditCheck` and returned to settle rather than rebuilt there), and, on the `--allow-skill-audit-miss` path, at the end of the bypass reason recorded in `SUMMARY.gateBypasses`, where `<ids>` are the ids of `ctx.draft.tasks`, in draft order, whose `ctx.progress.tasks[id]?.hooksObserved === false`, joined by `, `; the outcome is unchanged (refuse without the flag, pass with the bypass recorded with it); the dry run and the real run still report the same refusal text; and when no row has `hooksObserved: false` (all true, or the key absent), the refusal line, the dry-run reason and the bypass reason are byte-identical to today's.

### AC-4: Doctor reports host-hook liveness during BUILD
Given `cadence doctor` runs
When the loop is in BUILD and host hooks are installed in the repository (as in AC-2)
Then a check named `host-hooks-liveness` (complementing the existing `host-hooks` and `codex-hooks` checks, which prove the hooks are installed, not that they fire) reports severity `warning` when `isHookLive(state.session.lastHookEventAt, now)` is false, with a message that names the last stamp (or says none was recorded) and says to start the session in the repository root so the installed host config path(s) load, and severity `ok` when it is true; when the loop is not in BUILD it reports `ok` with a "not in BUILD" message; when no host hooks are installed it reports `ok` with a "not applicable — no host hooks installed" message; the check never reports severity `error`; and an unreadable state degrades to `ok` with a "not determinable" message rather than throwing.

### AC-5: Docs, changeset and doc test record the behavior
Given the behavior in AC-1 to AC-4
When the phase settles
Then `DESIGN.md` §11 describes the `lastHookEventAt` stamp, the 30-minute window, the three places the condition is reported, and the accepted false-negative path where a host-cli verifier child (e.g. `codex` under `CADENCE_HOST_CLI_BIN=codex` with project Codex hooks) fires project hooks and stamps; `docs/reference/config.md`'s `## skillAudit` section says a miss names the tasks recorded without live hooks; `docs/reference/commands.md` documents the `build task` notice, adds `host-hooks-liveness` to the doctor check table and to the `--fix` manual classification, and adds `lastHookEventAt` to the `state load` reset list; a `.changeset/*.md` bumps `@thomas-powers-jr/cadence-core` and `@thomas-powers-jr/cadence-types` by minor; a new doc-content test `packages/core/tests/docs/hook-liveness-docs.test.ts` asserts `DESIGN.md` contains `lastHookEventAt`, `docs/reference/config.md` contains `hooksObserved`, and `docs/reference/commands.md` contains both `host-hooks-liveness` and `lastHookEventAt`; and `packages/core/tests/docs/phase341-state-save-load-docs.test.ts` includes `lastHookEventAt` in its reset-field loop.

## Boundaries

- Do NOT change the skill-audit outcome: a shortfall still refuses without `--allow-skill-audit-miss`, and the bypass is still recorded. The new text only explains; it never turns a miss into a pass.
- Do NOT add a `cadence skill record` command, an MCP recording tool, or any other path for an agent to record its own skill invocations (option 2 of the rec, not chosen).
- Do NOT change `.claude/settings.json`, `.codex/hooks.json`, the host installers, or the host shims; the cause is the session's start folder, not the hook wiring.
- Do NOT change `SummaryZ` or the SUMMARY hash inputs; the explanation travels in the existing free-text bypass reason.
- Do NOT add a config knob for the 30-minute window or the 60-second throttle (constants; YAGNI).
- Do NOT add a runtime dependency.
- Do NOT stamp `lastHookEventAt` through `backend.commit` (it would advance `revision` mid-settle; see phase 305 / issue #500), and do NOT stamp before the event's handler has run.
- Do NOT write `hooksObserved` from `cadence block`, `cadence needs-context`, `tutorial` or `demo`; key-absent rows count as observed.
