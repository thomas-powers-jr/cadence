# 310-01 — DRAFT frontmatter parser rejects CRLF line endings

## Objective

`parseDraftMd` normalizes CRLF line endings before parsing so a DRAFT.md written or rewritten on Windows parses correctly instead of failing with a misleading "missing frontmatter" error.

## Acceptance Criteria

### AC-1: CRLF-terminated DRAFT.md parses identically to its LF equivalent
Given a well-formed DRAFT.md (valid frontmatter, Objective, Acceptance Criteria, Tasks, Boundaries sections) saved with `\r\n` line endings
When it is parsed by `parseDraftMd` (directly, or via `cadence draft check`)
Then parsing succeeds — no "missing frontmatter" error — and the resulting `Draft` object is field-for-field identical to parsing the same content saved with `\n` line endings, with no stray `\r` characters left in any string field (objective, AC given/when/then, task action/verify/files, boundaries)

### AC-2: A genuinely malformed frontmatter delimiter still fails loud
Given a DRAFT.md whose frontmatter delimiter is actually missing or malformed (e.g. no closing `---`), regardless of line-ending style
When it is parsed by `parseDraftMd`
Then parsing still throws the existing "DRAFT.md missing frontmatter" `CadenceError` — CRLF normalization must not mask a real structural problem

## Tasks

### T1: Normalize CRLF to LF once at parseDraftMd's entry point
- files: `packages/core/src/parse/draft-parser.ts`, `packages/core/tests/parse/draft-parser.test.ts`
- action: In `parseDraftMd`, replace all `\r\n` with `\n` in `raw` before it is passed to `parseFrontmatter`/`stripFrontmatter`/`extractSection` (a single `raw.replace(/\r\n/g, '\n')` at the top of the function is sufficient — every downstream regex already assumes bare `\n`). Add unit tests: (a) a full CRLF-terminated DRAFT.md fixture (frontmatter + all four sections + a multi-line AC and task) parses to the exact same `Draft` object as its LF equivalent, with no `\r` substring anywhere in any string field; (b) a DRAFT.md with a genuinely missing/malformed frontmatter delimiter (both LF and CRLF variants) still throws `CadenceError('DRAFT.md missing frontmatter')`.
- verify: `pnpm --filter @thomas-powers-jr/cadence-core test -- draft-parser.test.ts`
- done: AC-1, AC-2
- stop: `draft-parser.test.ts` passes, including the new CRLF-round-trip and still-fails-on-real-malformation cases

## Boundaries

- Do NOT touch the DRAFT writer/serializer (`draft-mutate.ts` or wherever DRAFT.md is written back out) — it already emits `\n` and is out of scope for this phase.
- Do NOT fix the identical frontmatter pattern in `spec-parser.ts` or `ui-spec-parser.ts` — no recommendation covers them; leave for a future phase.
- Do NOT fix `rec-20260805-003` (task `action:` field truncates multi-line content) even though it lives in this same file — tracked as a separate recommendation, separate phase.
