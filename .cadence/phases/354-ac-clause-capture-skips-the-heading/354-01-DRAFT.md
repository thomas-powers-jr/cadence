# 354-01 — AC clause capture skips the heading

## Objective

Stop a capitalised `Then ` (or `When `, or `Given `) in an AC heading, or a `Then ` earlier in the AC's own Given text, from starting that clause's captured text early (rec-20261124-001). Today `parseAcceptanceCriteria` in `packages/core/src/parse/draft-parser.ts` and its copy in `packages/core/src/parse/spec-parser.ts` capture each clause with an unanchored regex (`/Then\s+([\s\S]+)/` and the like) run over the whole AC block, heading included, so phase 350's first DRAFT parsed AC-1's Then-text as `clause⏎Given …`, and deep-verify, plan-review, spec-review and the phase 350 `UNBOUNDED_AC_THEN` scan all read the garbled text. A plain line-start anchor is not the fix: measured on 2026-11-27 over the 430 DRAFT and SPEC files in `.cadence/phases` (2015 ACs), anchoring the labels to line start changes 58 fields and blanks 56 of them (54 in phase 46), because older DRAFTs (phase 46, for example) write an AC on one line as `Given …, When …, Then …`. After this phase one shared pure function, `parseAcClauses(block)` in a new `packages/core/src/parse/ac-clauses.ts`, captures the three clauses for both parsers by the clause rule, and measured over the same corpus it changes exactly two fields, both heading-induced (phase 157's AC-2 and AC-3).

Definitions used by AC-1 to AC-7. A label is the word `Given`, `When` or `Then` followed by one whitespace character, matched with no word boundary before it. The clause rule: the AC's heading line (the block's first line) is never searched; the Given label is found first, from the body's first character; the When label is found from one character past the Given label's start, or from the body's first character when there is no Given label; the Then label is found from one character past the When label's start, else one character past the Given label's start, else the body's first character; each label is found at the first line start that carries it within its range, and only when no line start carries it, at its first inline occurrence in that range; each clause's text is captured from its label with today's terminators (Given up to the next line-start `When ` or `Then `, When up to the next line-start `Then `, Then to the end of the block) and trimmed. The legacy capture: today's three regexes run over the whole block, kept verbatim in the corpus test as the reference. The pinned corpus: the `*-DRAFT.md` and `*-SPEC.md` files directly under a `.cadence/phases/` directory whose name is a number `N` or starts with `N-`, with `N` at most 353 (430 files on 2026-11-27).

## Acceptance Criteria

### AC-1: The clause rule on four named blocks
Given `parseAcClauses` from `packages/core/src/parse/ac-clauses.ts`
When it is called on the four example blocks named below
Then (a) `### AC-1: words in a Then clause⏎Given g⏎When w⏎Then t` returns `{ given: 'g', when: 'w', then: 't' }`; (b) `### AC-1: x⏎Given a list. Then more⏎When w⏎Then t` returns `{ given: 'a list. Then more', when: 'w', then: 't' }`; (c) the one-line block `### AC-1: x⏎Given g, When w, Then t.` returns `{ given: 'g, When w, Then t.', when: 'w, Then t.', then: 't.' }`, the legacy capture's result for that block; (d) `### AC-1: When and Then⏎Given g` returns `{ given: 'g', when: '', then: '' }`.
