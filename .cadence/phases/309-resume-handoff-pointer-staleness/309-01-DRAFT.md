# 309-01 — locateFreshestHandoff compares generated_at even when the lastHandoff pointer resolves

## Objective

locateFreshestHandoff() must rank the lastHandoff pointer's file by generated_at against the SESSION-*.md glob instead of returning it unconditionally whenever it exists on disk, so cadence resume / resume --list never silently serve a stale handoff when a newer session doc lands without the local state.json pointer being rewritten (rec-20260917-001). The pointer going stale is inherent to state.json being gitignored and per-checkout — a SESSION doc merged from another session/branch never rewrites a different checkout's local pointer — not a bug in how run-handoff.ts stamps it; that stamping path is out of scope (see Boundaries).

## Acceptance Criteria

### AC-1: stale pointer is superseded
Given state.json's lastHandoff names a SESSION-*.md file that exists but is strictly older (by generated_at, falling back to the filename date) than another SESSION-*.md doc in the same .cadence/handoff/ dir
When locateFreshestHandoff() resolves the freshest handoff
Then it returns the newer doc, not the pointer's file, and the result's supersededPointer field names the pointer that was superseded

### AC-2: fresh or tied pointer is preserved, no false notice
Given state.json's lastHandoff names a SESSION-*.md file that is itself the freshest doc, or ties another doc's ranking key exactly
When locateFreshestHandoff() resolves the freshest handoff
Then it returns the pointer's file (ties resolve in the pointer's favor, not by mtime) with no supersededPointer field set, matching current behavior with zero false-positive notices

### AC-3: pointer file is never silently dropped from candidacy
Given the lastHandoff pointer resolves to a file that exists but has no parseable generated_at and no SESSION-YYYY-MM-DD date in its filename
When locateFreshestHandoff() ranks candidates
Then the pointer's file is still included in the ranked set (never excluded by the SESSION-*.md filter or an unparseable key) so it can still win or, if it loses, its loss is visible via supersededPointer rather than silently vanishing

### AC-4: resume surfaces a loud notice when it serves a superseded pointer
Given runResume()'s local-resolve path returns a LocatedHandoff with supersededPointer set
When cadence resume (CLI) or resumeService (MCP) renders the result
Then ResumeResult carries supersededHandoffPointer (parallel to the existing danglingHandoffPointer) and both the CLI and MCP resume paths print a loud notice naming the superseded pointer and the doc actually served, mirroring the existing dangling-pointer notice pattern

### AC-5: resume --list / sibling-aware candidate gathering reflects the fix
Given gatherHandoffCandidates() calls locateFreshestHandoff() for the local worktree with a stale lastHandoff pointer and a strictly newer local SESSION-*.md doc present
When cadence resume --list (or an equivalent gatherHandoffCandidates() call) runs
Then the local candidate reflects the freshest local doc, not the stale pointer's doc, correcting candidates.test.ts's prior "pointer honored over merely-freshest-on-disk" expectation

### AC-6: full suite, typecheck, lint stay green
Given the fix, updated tests, and new regression coverage are in place
When pnpm turbo run lint typecheck test build runs
Then it exits successfully with no failing tests across packages/core and packages/types

## Boundaries

- DO NOT modify run-handoff.ts's `state.session.lastHandoff` stamping logic — investigation confirmed it is unconditional except under the explicit `--no-stamp` flag; the staleness this phase fixes comes from state.json being gitignored/per-checkout (a merged SESSION doc from another session/branch never rewrites a different checkout's local pointer), which is a separate, already-understood design property, not a second bug to fix here.
- DO NOT extend supersededPointer/dangling-pointer notice plumbing to `resolveSiblingCandidate()` (run-resume.ts) — sibling candidates are resolved via `gatherHandoffCandidates()` + direct `readFile`, never call `locateFreshestHandoff()`/`localResolve()`, and already surface `path` + `generatedAt` for visual comparison in the candidate list; leaving that gap as-is is intentional for this phase.
- DO NOT change existing danglingPointer behavior, fields, or tests — supersededPointer is strictly additive alongside it.
- DO NOT remove or weaken existing tests to make new coverage pass — re-fixture in place, keep every existing coverage-gate token (AC-9, AC-10, AC-11, AC-12, 273-01/AC-1, 273-01/AC-2) inside asserting blocks.
- DO NOT refactor unrelated handoff/resume code (pick.ts, retention.ts, brief.ts, remote-freshness.ts) while implementing this fix.
