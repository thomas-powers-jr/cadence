## Code review findings

- packages/checkpoint/src/install.ts: HIGH — On Windows, rename replaces settings.json with a temp file inheriting the parent DACL, dropping explicit ACLs. Secrets in its env block may become readable by directory principals. (line 447)
- packages/checkpoint/src/install.ts: MEDIUM — Atomic rename replaces a symlinked settings file itself, leaving its target unchanged and breaking dotfile-manager links. Detect/reject symlinks or update their target. (line 447)
- packages/checkpoint/src/install.ts: MEDIUM — Only some shell builtins are rejected. Commands such as `alias foo` or `cd dir` can be installed, then fail or change semantics under the no-shell spawn. (line 172)
- packages/checkpoint/src/sensor.ts: HIGH — All inner stdout is buffered until exit. A verbose or non-terminating statusline grows memory without bound and never renders; stream output with backpressure instead. (line 322)
- packages/checkpoint/src/sensor.ts: MEDIUM — A recording continues after the deadline; an older delayed invocation can finish after a newer one and overwrite reading.json with stale data. (line 371)
- packages/checkpoint/src/state.ts: MEDIUM — Any string is accepted for `since`, so a corrupt non-ISO timestamp is treated as valid despite the state-file contract and can break timestamp-based consumers. (line 190)
