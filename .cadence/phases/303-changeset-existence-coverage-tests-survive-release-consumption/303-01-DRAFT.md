# 303-01 — changeset-existence coverage tests survive release consumption

## Objective

Two coverage-token tests (settle.test.ts 300-01/AC-5, check-lockfile-overrides.test.ts 301-01/AC-3) hard-assert that a specific .changeset/*.md file exists on disk. A release's 'changeset version' step deletes consumed changeset files, so the very next release will permanently red both tests. Make both tests tolerate changeset consumption while still failing if the underlying fix was never shipped with a changeset at all.

## Acceptance Criteria

### AC-1: both coverage-token tests tolerate changeset consumption
Given a shared, extracted helper function `changesetEvidencePresent` (taking a changeset path, `packages/core/CHANGELOG.md`'s path, and a fix-specific discriminator string as arguments — not inline logic in the test files) that returns true when "the changeset file exists and names the package" OR "`packages/core/CHANGELOG.md` contains the discriminator verbatim"
When settle.test.ts's 300-01/AC-5 test and check-lockfile-overrides.test.ts's 301-01/AC-3 test call that helper with the real paths and their pinned discriminator strings — `unresolved-target` for the lockfile fix, `already-shipped draft's canonical` for the settle fix (both confirmed, by live grep of `packages/core/CHANGELOG.md` during drafting, to have zero occurrences in the repo today — neither is the package name, which is not distinguishing since it appears throughout CHANGELOG.md; both changesets bump `@thomas-powers-jr/cadence-core` specifically, so both land in `packages/core/CHANGELOG.md`, not a per-package-guessed path)
Then the helper returns true whether the real changeset file is present (today) or has been deleted by `changeset version` (post-release)

### AC-2: the coverage token stays meaningful — it still fails if the fix genuinely shipped without a changeset
Given a unit test calls the extracted helper directly with a nonexistent changeset path and CHANGELOG.md content that does NOT contain the discriminator string
When the helper runs
Then it returns/asserts false, proving the token cannot be satisfied by doing nothing
