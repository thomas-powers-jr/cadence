# 338-01 — Clear the zod, body-parser and undici high advisories with override floors

## Objective

Clear the three high advisories that turn `security-success` red on every PR (rec-20261027-002, high). `main` itself went red in the scheduled security run on `572b331` (2026-10-26; green on push 2026-10-22), and PR #583 hit it on 2026-10-27. Reproduced 2026-10-27 with `node scripts/check-audit-exceptions.mjs` (root) and `node scripts/check-audit-exceptions.mjs website`, which run `pnpm@11.13.0 audit --json`: the root reports GHSA-mrhx-c7xc-m3w5 (zod `<4.6.6`, patched `>=4.6.6`; zod 4.4.3 via `@anthropic-ai/sdk`) and GHSA-27r3-jxmh-p828 (body-parser `>=2.0.0 <2.4.0`, patched `>=2.4.0`; body-parser 2.3.0 via `@modelcontextprotocol/sdk`); the website reports GHSA-mrhx-c7xc-m3w5 again (zod 4.4.3 via `@astrojs/starlight>@astrojs/sitemap`) and GHSA-xjj6-f33q-929c (undici `>=8.0.0 <8.12.2`, patched `>=8.12.2`; undici 8.11.2 via `astro>unifont`). CI never reached the website step because the root step failed first, so fixing only the root would leave the job red. Fix it the phase 330/334 way, with durable, **major-scoped** caret `pnpm.overrides` floors in the two private manifests: root `zod@^4.0.0 → ^4.6.6` and `body-parser@^2.0.0 → ^2.4.0`; website `zod@^4.0.0 → ^4.6.6` and `undici@^8.0.0 → ^8.12.2`. The selectors are scoped to the affected major so no other major (a zod 3 or a body-parser 1.x under some future dependency) is dragged across a major boundary. Regenerate both lockfiles with `pnpm install`, never `pnpm update`. A throwaway worktree off `main` with the root floors already showed zod 4.6.7 and body-parser 2.4.0, a clean root audit, satisfied lockfile overrides, and a green `pnpm turbo run typecheck test build --force` (21/21 tasks), so the zod 4.4→4.6 minor bump is safe for the published packages' own zod use.
