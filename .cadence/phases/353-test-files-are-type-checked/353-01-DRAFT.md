# 353-01 — test files are type-checked

## Objective

Make a type error in a test file fail `pnpm typecheck` and CI (rec-20261125-004). Today each package's `tsconfig.json` includes only `src/**/*`, `tsconfig.base.json` excludes `tests` and `**/*.test.ts`, and vitest strips types at run time, so no command in the pipeline type-checks `packages/*/tests`. Measured on 2026-11-27 with a strict test config: checkpoint, host-claude-code, host-codex, host-toolkit and testkit have 0 errors, types has 5 errors in 3 files, and core has 289 errors in 62 files. After this phase the seven packages carry a `tsconfig.test.json` (noEmit, `src/**/*` plus `tests/**/*`, rootDir at the repo root so tests may import sibling packages' source) and their `typecheck` script runs it after the existing build-config check. Types' 5 errors are fixed. Core's 62 erroring files are listed in its `tsconfig.test.json` `exclude` as a checked-in baseline, and a doc-content test makes that baseline a ratchet: it may shrink and may not grow. Burning down core's baseline is later phases' work.

Definitions used by AC-1 to AC-6. The seven packages: `checkpoint`, `core`, `host-claude-code`, `host-codex`, `host-toolkit`, `testkit`, `types`. The test-typecheck script: `tsc -p tsconfig.json --noEmit && tsc -p tsconfig.test.json`. The baseline: the 62 core test paths (relative to `packages/core`) that fail the test config on main `ed1489d1`, frozen as `BASELINE` in the ratchet test; paths are relative to `packages/core` (the measurement list with its `packages/core/` prefix stripped). The baseline cap: the literal 62, compared against the baseline's length. The test config shape: `extends` `../../tsconfig.base.json`; `compilerOptions` exactly `{ noEmit: true, rootDir: "../..", composite: false, declaration: false, declarationMap: false }`; `include` `["src/**/*", "tests/**/*"]`. The files are comment-free JSON.
