# 353-01 — test files are type-checked

## Objective

Make a type error in a test file fail `pnpm typecheck` and CI (rec-20261125-004). Today each package's `tsconfig.json` includes only `src/**/*`, `tsconfig.base.json` excludes `tests` and `**/*.test.ts`, and vitest strips types at run time, so no command in the pipeline type-checks `packages/*/tests`. Measured on 2026-11-27 with a strict test config: checkpoint, host-claude-code, host-codex, host-toolkit and testkit have 0 errors, types has 5 errors in 3 files, and core has 289 errors in 62 files. After this phase the seven packages carry a `tsconfig.test.json` (noEmit, `src/**/*` plus `tests/**/*`, rootDir at the repo root so tests may import sibling packages' source) and their `typecheck` script runs it after the existing build-config check. Types' 5 errors are fixed. Core's 62 erroring files are listed in its `tsconfig.test.json` `exclude` as a checked-in baseline, and a doc-content test makes that baseline a ratchet: it may shrink and may not grow. Burning down core's baseline is later phases' work.

Definitions used by AC-1 to AC-4. The seven packages: `checkpoint`, `core`, `host-claude-code`, `host-codex`, `host-toolkit`, `testkit`, `types`. The test-typecheck script: `tsc -p tsconfig.json --noEmit && tsc -p tsconfig.test.json`. The baseline: the 62 core test paths (relative to `packages/core`) that fail the test config on main `ed1489d1`, frozen as `BASELINE` in the ratchet test. The baseline cap: 62.

## Acceptance Criteria

### AC-1: The seven packages type-check their tests
Given the seven packages' `package.json` and `tsconfig.test.json` files after this phase
When the ratchet doc test reads them
Then the `typecheck` script of `checkpoint`, `core`, `host-claude-code`, `host-codex`, `host-toolkit`, `testkit` and `types` equals the test-typecheck script; their `tsconfig.test.json` extends `../../tsconfig.base.json`, sets `noEmit: true` and `rootDir: "../.."`, and has `include` equal to `["src/**/*", "tests/**/*"]`; and the `exclude` of the six packages other than core equals `["node_modules", "dist"]`.
Not covered: the build config `tsconfig.json`, which keeps its `src/**/*` include and emit settings; lint of test files (`eslint src` stays as it is); vitest's own typecheck mode, which stays off.

### AC-2: Core's baseline is a ratchet
Given the ratchet test's pure checker `checkTestTypecheckRatchet(excludes, baseline, exists, cap)`, which returns a list of problems, with `excludes` = core's `tsconfig.test.json` `exclude` entries other than `node_modules` and `dist`
When it is called with core's real `exclude`, `BASELINE`, a filesystem `exists` and cap 62, and with four named variations
Then the real call returns `[]` and `BASELINE` has 62 entries; adding `tests/cli/new-file.test.ts` to `excludes` alone returns `[{ kind: 'not-in-baseline', path: 'tests/cli/new-file.test.ts' }]`; removing `tests/checks/skill-audit.test.ts` from `excludes` alone returns `[{ kind: 'fixed-but-listed', path: 'tests/checks/skill-audit.test.ts' }]`; an `exists` that is false for `tests/checks/skill-audit.test.ts` returns `[{ kind: 'missing-file', path: 'tests/checks/skill-audit.test.ts' }]`; and a 63-entry baseline returns a problem of kind `over-cap`.
Not covered: detecting that a baseline file has started to type-check cleanly while still excluded (the checker does not run `tsc`; the next phase that fixes a file removes it from both lists); excluded files imported by an included test, which `tsc` still checks.

### AC-3: Types' test files type-check
Given `packages/types` after this phase, with an AC `name` added to the AC literals at `tests/plan.test.ts` lines 14, 56 and 87 and `tests/spec.test.ts` line 9, and the indexed access at `tests/intelligence.test.ts` line 426 narrowed
When the ratchet test runs the TypeScript compiler on `packages/types/tsconfig.test.json`
Then the compiler exits with status 0 and prints no `error TS` line.
Not covered: core's baseline files, which stay excluded; the behaviour of types' tests, which the types test suite still checks.

### AC-4: Docs and records

When the phase settles
Then `CLAUDE.md`'s `pnpm typecheck` line in **Common commands** says it covers `src` and `tests`; `CLAUDE.md`'s **Enforcement layers** section has a bullet naming `tsconfig.test.json`, core's baseline and `packages/core/tests/docs/test-typecheck-ratchet.test.ts`; `.cadence/ROADMAP.md` has a `### Phase 353` entry and `.cadence/MILESTONES.md` a `- **Phase 353**` bullet; and a doc-content test asserts that `CLAUDE.md` contains `tsconfig.test.json` and `test-typecheck-ratchet.test.ts`.
Not covered: a changeset (dev tooling only, no published behaviour changes, as in phases 325, 326 and 329); `CONTRIBUTING.md`; CHANGELOG.md, which the release writes.
