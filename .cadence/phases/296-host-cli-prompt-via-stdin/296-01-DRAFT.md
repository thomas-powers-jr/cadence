# 296-01 — Pass the host-cli prompt on stdin so it is not bounded by the OS argv limit

## Objective

`buildInvocation` puts the entire host-cli prompt — the deep-verify diff
included — into the argv array (`host-cli-client.ts:275` for codex, `:278` for
claude), and `realSpawn` opens the child with `stdio: ['ignore', 'pipe', 'pipe']`
so stdin is deliberately not a path. Windows caps a command line at 32,767
characters. Any prompt above that throws `spawn ENAMETOOLONG`, the provider
degrades to `mock`, and the settle reports `no linked test found` for every AC —
a run that looks like it verified and verified nothing. `verifier.diffCapBytes`
exists only to stay under that ceiling; this repo's own `.cadence/config.json`
sets it to the library default `262144`, which is unreachable on Windows.

Both binaries already accept the prompt on stdin, verified against the real
binaries on 2026-09-07: `codex exec --json --skip-git-repo-check -` read a
53,960-byte prompt (`input_tokens: 65151`, no truncation), and
`claude -p --output-format json` with the prompt piped returned
`"is_error": false`. Move the prompt from argv to stdin for both families. The
argv ceiling disappears; what bounds the diff afterwards is the model's context
window and cost, not the operating system.

## Acceptance Criteria

### AC-1: the prompt is never an argv element
Given a host-cli call for either family
When `buildInvocation` builds the argument array
Then the prompt string is absent from the returned argv, and the array's length does not grow with prompt size

### AC-2: both families are invoked in their documented stdin form
Given the configured binary is codex, and separately claude
When the invocation is built
Then codex receives `exec --json --skip-git-repo-check [-m model] -` and claude receives `-p --output-format json [--model model]` with no positional prompt

### AC-3: the prompt is written to stdin and the stream is closed
Given a spawned host-cli child process
When the call runs
Then the full prompt is written to the child's stdin and the stream is ended exactly once, so a CLI that blocks on EOF does not hang

### AC-4: a stdin write error is surfaced, not fatal
Given the child exits before the prompt is fully written and stdin emits EPIPE
When the write fails
Then the error is captured and rejected as a `HostCliError`, and no unhandled stream error can take the process down

### AC-5: a prompt larger than the OS argv ceiling completes
Given a prompt longer than 32,767 characters
When the host-cli client runs it against a fake spawn
Then the call resolves normally and the received stdin content equals the prompt in full, with no truncation and no `ENAMETOOLONG`

### AC-6: existing host-cli behaviour is unchanged
Given the surrounding guards — spawn timeout, external `AbortSignal`, the `CLAUDECODE=1` self-invocation refusal, JSON envelope parsing and the repair harness
When the full core suite, typecheck and lint run
Then every pre-existing host-cli test passes unmodified and no guard changes behaviour

### AC-7: the operator-facing bound is documented
Given `diffCapBytes` no longer exists to dodge an OS limit
When the config reference is read
Then it states that the prompt travels on stdin and that the cap now bounds model context and cost rather than a command-line length

## Boundaries

- DO NOT change the default value of `verifier.diffCapBytes`. The library default `262144` becomes genuinely reachable once the ceiling is gone; changing it is a separate decision.
- DO NOT touch `packages/core/tests/verify/per-task.test.ts` or `packages/core/tests/verify/json-repair.test.ts`. Their fake process objects must keep type-checking against the widened interface, which is the point of making the new member optional.
- DO NOT alter the spawn timeout, the `AbortSignal` path, or the `CLAUDECODE=1` self-invocation guard.
- DO NOT switch any stdio channel to `'inherit'`; that is reserved for the interactive `init`/`start` launcher.
- DO NOT add a size threshold that keeps a second argv code path alive. One path, always exercised.
