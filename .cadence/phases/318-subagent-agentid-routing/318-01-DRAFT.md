# 318-01 — subagent agentid routing

## Objective

Make Claude Code's subagent task-redundancy chain reachable through the real hook path. `packages/host-toolkit/src/routing.ts`'s `routeHookEvent` already extracts `agentId`/`agentType` (camelCase) from Claude Code's snake_case `agent_id`/`agent_type` via `extractPayload`, but builds the translated stdin by copying only `files`/`skill`, so core's `cadence hook` (which reads camelCase only, `packages/core/src/cli/commands/hook.ts`) always sees `ctx.agentId === undefined`. That silently disables `handleSubagentStart`'s baseline snapshot and its "do not redo" context nudge, post-tool-edit's per-subagent `touchedFiles` tracking, and `handleSubagentResult`'s SubagentStop safety net in both `warn` (default) and `block` mode. The edit-time check in `handlePreToolEdit` does not depend on `agentId` and is out of scope. Claude Code's current hooks docs (code.claude.com/docs/en/hooks, fetched 2026-09-26, `ev-20260926-007`) confirm `agent_id`/`agent_type` are present on SubagentStart/SubagentStop and on PreToolUse/PostToolUse fired inside a subagent, so copying the two fields in the adapter's translation step is sufficient. Source: `rec-20260926-001` (+ `dec-20260926-001`, `ev-20260926-006/007/008`).

## Acceptance Criteria

### AC-1: translated stdin carries camelCase agent identity
Given a Claude Code hook payload with snake_case `agent_id`/`agent_type` for SubagentStart, SubagentStop, and a PostToolUse Edit fired inside a subagent
When `routeHookEvent` from `packages/host-toolkit/src/routing.ts` translates it
Then the parsed `translatedStdin` has `agentId`/`agentType` equal to the input's `agent_id`/`agent_type` (alongside the existing `files` for the edit event), and a main-thread payload with no `agent_id` produces a `translatedStdin` with no `agentId`/`agentType` keys

### AC-2: warn-mode safety net fires through the real shim
Given a temp repo in BUILD with an active draft whose T1 (owning `src/a.ts`) is DONE in PROGRESS.json and the default `redundantWorkEnforcement: warn`
When the built host-claude-code shim (`dist/cli.js hook`) is fed, in order, a SubagentStart, a PostToolUse Edit of `src/a.ts`, and a SubagentStop — each carrying only snake_case `agent_id`/`agent_type` — spawning the built core CLI
Then SubagentStart's stdout carries the "Do not redo T1" nudge, a `redundant-task-work` anomaly naming T1/DONE is recorded, every call exits 0, and the agent's `subagentBaselines` entry is gone from `state.json` afterwards

### AC-3: block-mode safety net blocks through the real shim
Given the AC-2 setup with `redundantWorkEnforcement: block`, and the edit delivered so that the edit-time check does not refuse it first (a PostToolUse event, which only records touched files)
When the same SubagentStart → PostToolUse → SubagentStop sequence is fed through the built shim with snake_case fields only
Then the SubagentStop call surfaces the `redundantWorkEnforcement=block` message naming T1, asserted on combined stdout+stderr so the assertion is transport-neutral with respect to phase 317's stdout-JSON block transport

### AC-4: Claude Code declares agent identification
Given `packages/host-claude-code/src/capabilities.ts`
When the adapter's capabilities are read
Then `agentIdentification` is `true`, and host-codex's `agentIdentification: false` is unchanged
