# 335-01 — cadence handoff prune never deletes a git-tracked doc

## Objective

Make the handoff retention prune keep every git-tracked SESSION doc (rec-20261016-004, high). Every `cadence handoff` run in this repo prunes `.cadence/handoff/SESSION-*.md` past `handoff.retain` (10), including docs already committed. Each run therefore leaves tracked deletions that the operator must `git restore` (eight recorded occurrences through 2026-10-16, a ninth on 2026-10-20, then 10 and 12 docs on 2026-10-21 and 2026-10-22). This contradicts `docs/reference/config.md`'s "never silently destructive" claim. `selectPrunable` (`packages/core/src/handoff/retention.ts`) is pure keep-count arithmetic, and `pruneHandoffDir` unlinks its result with no notion of tracking. Both prune entry points go through `pruneHandoffDir`: `run-handoff.ts:106` and the `doctor --fix` handoff-retention repair (`doctor/fix.ts:193`). The fix belongs there, as pure core plus impure shell: (1) `selectPrunable` gains an optional fourth argument, `tracked: ReadonlySet<string>` (default empty), and filters those names out of the prune list it computes today. Its output without the argument is byte-identical to the current output. (2) `pruneHandoffDir` gains an optional `deps` argument with an injectable `listTracked(dir)` and `stderr`. The default lister runs a best-effort `git ls-files` (fixed arg array, 5 s timeout, `windowsHide`, never throws) in the handoff dir and returns basenames, or `null` on any failure, which means no protection, as today. This mirrors `listTrackedCadenceOwnedPaths` (`doctor/run.ts:256`). (3) When at least one tracked doc that the budget would have pruned is kept, exactly one stderr line names the count and the fix (Quiet Fallback: a changed decision prints). (4) `run-handoff`'s `pruned` stays the list actually unlinked, and its `deps.prune` seam signature is unchanged. Tracked docs are protected unconditionally, with no config knob. Patch changeset for cadence-core.

## Acceptance Criteria

### AC-1: tracked docs survive the prune
Given a handoff dir holding 5 `SESSION-*.md` docs whose newest is untracked and 2 of whose 4 older docs are git-tracked, with `retain` 1
When `pruneHandoffDir` runs with an injected `listTracked` that reports those 2 basenames
Then both tracked docs still exist on disk, `pruned` lists exactly the 2 untracked docs beyond the budget in lexicographic-descending order, and the newest doc is kept

### AC-2: an unavailable lister changes nothing
Given the same 5-doc dir with `retain` 1, and an injected `listTracked` that throws (one case) or resolves `null` (a second case), standing in for a non-git directory, a missing git binary or a timeout
When `pruneHandoffDir` runs
Then it does not throw, it unlinks and returns exactly the 4 docs that `selectPrunable(names, 1, current)` selects without a tracked set (today's behavior), and its injected `stderr` receives nothing; and, given `runHandoff` with `retain` set in a `tempRepo` that is not a git repository (the default lister's real failure path), the new doc is written, `pruned` equals today's selection, and nothing reaches `process.stderr`

### AC-3: one stderr notice, only when a tracked doc was kept
Given a prune in which 2 tracked docs fall outside the budget (one case), one in which the only tracked doc is inside the budget (a second case), and one with no tracked docs (a third case)
When each `pruneHandoffDir` run completes with an injected `stderr`
Then the first case writes exactly one line, `handoff: kept 2 git-tracked SESSION doc(s) past handoff.retain; committed SESSION docs are kept, sweep them in a housekeeping PR`, and the second and third cases write nothing, so the count is the tracked docs the budget would have pruned, not all tracked docs

### AC-4: selectPrunable without a tracked set is unchanged
Given every input/output pair the pre-phase `tests/handoff/retention.test.ts` fixtures pin (keep-count window, `current` force-retained, same-day label ties, empty input)
When `selectPrunable` is called with three arguments, and again with an explicit empty `Set` as the fourth
Then both calls return arrays equal to the pre-phase expectations, and with a non-empty tracked set no tracked name is ever returned while the `current` invariant and descending order still hold

### AC-5: a real git repository keeps its committed handoff docs through cadence handoff
Given a temp directory initialized as a git repository by the test, with `handoff.retain` 2, four committed `SESSION-*.md` docs and one older untracked doc
When `runHandoff` writes a new SESSION doc through its default prune (no injected `deps.prune`)
Then all four committed docs still exist, `git ls-files --deleted` prints nothing, `pruned` lists only the untracked doc, and stderr carries exactly one notice naming 3 kept docs

### AC-6: doctor --fix keeps committed handoff docs too
Given a temp directory initialized as a git repository by the test, with `handoff.retain` unset and 12 committed `SESSION-*.md` docs, so `cadence doctor` warns on `handoff-retention`
When `applyFixes` runs the `handoff-retention` repair
Then `handoff.retain` is set to the default 10 as before, all 12 committed docs still exist, and `git ls-files --deleted` prints nothing

### AC-7: docs state that the pruner never deletes a tracked doc
Given `docs/reference/config.md`'s handoff section and `docs/reference/commands.md`'s `doctor --fix` auto row
When a doc test reads them
Then the `handoff.retain` row says it hard-deletes untracked `SESSION-*.md` docs past the budget and that git-tracked docs are never deleted by the pruner, the section no longer claims "no git introspection", and the `doctor --fix` row says committed docs are kept when it prunes to budget

- Do NOT change `handoff.retain`'s schema, default or keep-count semantics, and do NOT add a config knob: tracked docs are protected unconditionally.
- Do NOT change the `current`/`lastHandoff` always-retained invariant or the lexicographic-descending order.
- Do NOT edit `run-handoff.ts`, `doctor/fix.ts`, `HandoffDeps`, `HandoffResult` (no `protectedCount`: no doc test consumes the shape) or the `cadence handoff` CLI's `pruned` output line.
- Do NOT touch `cadence resume`, `handoff/locate.ts` or `handoff/candidates.ts`.
- Do NOT change the doctor `handoff-retention` check or its messages. Its "next write will self-heal" wording can now be wrong when the excess is tracked; record that as a follow-up recommendation at settle rather than fixing it here.
- Do NOT stage, commit or `git rm` anything from the pruner: its only git call is the read-only `ls-files`.
- Do NOT refactor `listTrackedCadenceOwnedPaths` into a shared helper or edit `doctor/run.ts`.
- Do NOT add a runtime dependency or edit `packages/testkit/**`.
