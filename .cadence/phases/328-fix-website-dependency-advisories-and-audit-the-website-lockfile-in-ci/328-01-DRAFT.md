# 328-01 — Fix website dependency advisories and audit the website lockfile in CI

## Objective

Clear the docs site's dependency advisories and close the CI gap that let them accumulate (rec-20260802-006). `website/` is its own pnpm project (`website/pnpm-workspace.yaml` declares `packages: []`; its own `website/pnpm-lock.yaml`), and the required `security-success` check's `audit` job runs `scripts/check-audit-exceptions.mjs` and `scripts/check-lockfile-overrides.mjs` against the repo root only, so nothing ever audits `website/`. On 2026-10-13 GitHub reported 37 open Dependabot alerts on `main`, 26 of them in `website/pnpm-lock.yaml`, including the only critical (`GHSA-26w7-cxv4-gfx2`, astro `<7.2.8`, remote code execution through AVIF image optimization) and every high. Measured the same day by running the CI gate's own pinned audit (`corepack pnpm@11.13.0 --pm-on-fail=ignore audit --json` in `website/`) through `extractHighSeverityAdvisories` and `decideAdvisories` against the real exceptions table: 1 critical, 12 high, 11 moderate and 2 low; the gate would report 13 failures. The 13 high/critical are astro (`GHSA-26w7-cxv4-gfx2`), devalue (`GHSA-j22f-vq7h-c4qm`, `GHSA-mcm9-63f2-9j32`, `GHSA-x5rw-q4pp-hg5g`), sharp (`GHSA-rgj7-g3m4-5g8c`, `GHSA-wq5f-xc86-pv6w`), svgo (`GHSA-w27v-7q3p-w38r`), js-yaml (`GHSA-2883-xcg3-v3hh`), smol-toml (`GHSA-7w5x-hrqm-74c2`), source-map-js (`GHSA-68fv-2mgg-jv7q`), http-cache-semantics (`GHSA-ch52-4w7c-c8xp`), and brace-expansion (`GHSA-qhr7-859c-m2p7`, `GHSA-6j4f-fj2g-mc7p`, via typedoc → minimatch). Every one has a release outside its vulnerable range (astro 7.3.8 is inside `website/package.json`'s `^7.2.2`; `http-cache-semantics` is vulnerable `<=4.2.0` and 4.3.0 exists, although Dependabot lists no patched version), so the fix is an in-range refresh plus range-keyed `pkg@<floor` overrides in `website/package.json` where a parent's range holds a vulnerable version, in the pattern phases 253/321/324 established, and no exception row. Then both audit scripts gain an optional project-directory argument and the `audit` job runs each once more against `website/`; `pnpm audit` and the override check read only lockfile and manifest, so this adds steps, not an install or a job (253-01/AC-4's pin stays green). The exceptions table stays single, at the repo root, and covers both projects. `website/` is not published and the scripts are repo tooling, so no published package changes and no changeset is due (phase 326 precedent). Out of scope, deliberately: the 11 root-lockfile moderates (rec-20261008-002, the next phase), `@changesets/cli` 3.x (Dependabot #474, rec-20261010-007), a `@astrojs/starlight` 0.42 minor bump unless a fix forces it, `vitest` 5 (Dependabot #484) and the `docs.yml` action-pin drift (rec-20260805-001).
