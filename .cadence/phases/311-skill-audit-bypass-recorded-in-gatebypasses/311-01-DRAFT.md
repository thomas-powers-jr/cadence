# 311-01 — skill-audit bypass recorded in gateBypasses

## Objective

`--allow-skill-audit-miss` writes a `GateBypass` entry to `SUMMARY.gateBypasses`, so a settle that proceeded past a missing required skill is visible in the durable phase artifact instead of only on ephemeral stderr. This mirrors the `pack-resolution` direct-push precedent at `services/settle.ts:1201-1213`. skill-audit cannot use the registry's `gates[].skipReason` convention, because it is deliberately not a `Gate` enum member and is dispatched outside the Phase 44.1 registry, so it produces no `gates[]` entry at all — a direct `gateBypasses` push is the only available route. The bypass is today doubly unrecorded: `anomalyToGateBypass` has no `skill-audit-miss` case, and `emitSkillAuditMiss` writes straight to `notifier.notify()` so the event never joins the `anomalies` array that `gateBypassesFromAnomalies` consumes. `docs/cli.md` already describes this asymmetry accurately — line 268 omits the `gateBypasses` clause that line 269 carries for `--allow-unresolvable-pack` — so the old row documented the gap correctly rather than documenting an unmet expectation, and T3 updates both rows to match the new behavior. Source: `rec-20260917-004`; unblocks the pack-requirement phase whose own AC asserts this recording exists.

## Acceptance Criteria

### AC-1: bypass is recorded in the durable artifact
Given a phase whose required skill was not invoked and `--allow-skill-audit-miss` is passed to `settle run`
When settle completes and writes `SUMMARY.json`
Then `SUMMARY.gateBypasses` contains exactly one entry whose `gate` is `skill-audit`, whose `flag` is `--allow-skill-audit-miss`, whose `severity` is `warn`, and whose `reason` names the missing skill(s)

### AC-2: the existing stderr notice is preserved
Given the same bypassed settle as AC-1
When the command's stderr is inspected
Then the pre-existing `skill-audit: --allow-skill-audit-miss set; proceeding past N missing skill(s).` notice is still emitted, proving the durable record supplements the loud notice rather than replacing it

### AC-3: no false positive on the clean path
Given a phase where every required skill was invoked
When settle completes
Then `SUMMARY.gateBypasses` contains no entry whose `gate` is `skill-audit`

### AC-4: refusal behavior is unchanged
Given a phase where a required skill was not invoked and no bypass flag is passed
When settle runs
Then it refuses exactly as before with the existing message, and no `skill-audit` entry is written to `SUMMARY.gateBypasses`

### AC-5: the unenforceable path stays out of the bypass record
Given `telemetry.skillInvocations` is `false`, which makes the requirement unenforceable
When settle completes
Then the unenforceable warn anomaly is still emitted and no `skill-audit` entry appears in `SUMMARY.gateBypasses`, because recording `--allow-skill-audit-miss` there would name a flag the operator never passed; this path therefore remains unrecorded in the durable artifact and is tracked as a residual on `rec-20260917-004`, so this criterion is a regression guard and NOT an endorsement of that gap
