# 330-01 — Raise override floors past the 13 root moderate advisories

## Objective

Clear the 13 moderate advisories `pnpm audit` reports against the root `pnpm-lock.yaml` (`rec-20261008-002`; re-measured 2026-10-15 in this worktree: hono 4.13.1 ×4, ip-address 10.4.0 ×4, qs 6.15.3 ×2, fast-uri 3.1.7, vitest 4.1.10, @vitest/mocker 4.1.10; 0 high/critical) by raising durable `pnpm.overrides` floors in the root `package.json`, each a caret range at the strictest `patched_versions` the audit names: new keys `hono@<4.13.7: ^4.13.7` and `qs@<6.16.0: ^6.16.0` (production path via cadence-core's `@modelcontextprotocol/sdk`), the existing fast-uri key moved from `<3.1.6: ^3.1.6` to `<3.1.8: ^3.1.8`, the existing `ip-address@^10.0.0` target raised from `^10.3.1` to `^10.7.1`, and new keys `vitest@<4.1.11: ^4.1.11` and `@vitest/coverage-v8@<4.1.11: ^4.1.11` (dev-only; @vitest/mocker follows vitest's exact pin). Overrides, not a bare lockfile refresh, so the floors cannot drift back; vitest goes through overrides too because bumping only the root devDependency empirically left a duplicate 4.1.10 for the six workspace packages that declare `^4.1.10`, and editing those published manifests is unnecessary. Pre-draft probe (2026-10-15, this worktree): after the edit and `pnpm install`, `pnpm why hono -r` shows a single hono 4.13.13 (including the `@hono/node-server` peer path), the lockfile resolves qs 6.16.1, ip-address 10.7.4, fast-uri 3.1.8 and a single vitest / @vitest/mocker / @vitest/coverage-v8 4.1.12, `scripts/check-lockfile-overrides.mjs` passes 11/11 targets, and `pnpm audit` reports 0 vulnerabilities of any severity. Root overrides do not reach npm consumers and no published manifest changes, so there is no changeset. The rec's second question — whether the audit gate should start reporting moderate advisories on production paths — is out of scope here and is filed as its own follow-up recommendation at settle, not dropped.

### AC-2: every resolved instance in the committed lockfile is at or above its floor
Given the committed root `pnpm-lock.yaml`
When it is parsed with `parseLockfilePackages` and checked with `checkOverrideCoverage` against the real override targets
Then coverage has zero failures, every resolved hono, qs, fast-uri, ip-address, vitest, @vitest/mocker and @vitest/coverage-v8 instance is numerically at or above its patched floor (hono 4.13.7, qs 6.16.0, fast-uri 3.1.8, ip-address 10.7.1, vitest family 4.1.11), and the set of distinct resolved versions of each of vitest, @vitest/mocker and @vitest/coverage-v8 has exactly one member (the lockfile lists each package under both `packages:` and peer-suffixed `snapshots:` entries, so instances are counted by distinct version, not by entry)

### AC-3: the fix lives only in the private root manifest
Given every published `packages/*/package.json`
When their dependency specifiers are read off disk
Then cadence-core's `@modelcontextprotocol/sdk` range and every package's `vitest` devDependency specifier (`^4.1.10`) are unchanged, so no published package changes and no changeset is owed
