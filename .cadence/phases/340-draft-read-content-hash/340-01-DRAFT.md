# 340-01 — draft-read refuses only when the DRAFT's content changed since approve, not just its mtime

## Objective

The `draft-read` gate (Phase 23.1) refuses `settle run` when DRAFT.md's mtime is newer than `state.draftReadAt`. An mtime is not evidence of an edit. A `git checkout`, `git switch`, clone, pull, or file copy on another machine gives the DRAFT a fresh mtime with identical content, and settle then refuses an unedited DRAFT. The only way past it today is the `--allow-stale-draft` bypass. Cadence Studio's `cadence-state load --allow-build` documents exactly this trap when it carries a mid-BUILD loop between PCs, and the planned `cadence state save/load` (phase 341) would inherit it.

This slice makes the gate check content as well as mtime:
- `draft approve` also stamps a new optional `state.draftReadHash`: the sha256 of the DRAFT's text after phase 339's `normalizeText` (one leading BOM stripped, CRLF and lone CR folded to LF), so line-ending and BOM churn from git `autocrlf` or Windows tooling does not count as an edit.
- The gate refuses only when the mtime is newer **and** the current normalized hash differs from the stamp. When the mtime is newer but the hash matches, it passes and says so on stderr.
- When there is no stamp (state written before this phase), or the DRAFT cannot be read for hashing, the gate behaves exactly as today: mtime only.

The schema change is additive. No gate set, tier × profile cell, flag, or refusal message changes.

## Acceptance Criteria

### AC-1: approve stamps a normalized content hash beside draftReadAt
Given a PENDING DRAFT that passes every approve gate
When `cadence draft approve` moves the loop to BUILD
Then:
- `state.json` carries `draftReadHash`: 64 lowercase hex characters, equal to the sha256 of `normalizeText(<DRAFT file contents>).text`, written in the same commit as `draftReadAt`;
- the same DRAFT saved as LF, CRLF, BOM+LF, or BOM+CRLF yields the same `draftReadHash`;
- a DRAFT whose text differs by one character yields a different `draftReadHash`;
- a `state.json` with no `draftReadHash` key still parses, with the field `null`; `emptyState()` sets it to `null`; a value that is not 64 lowercase hex characters is rejected by `CadenceStateZ`.

### AC-2: a fresh mtime over unchanged content passes, loudly
Given an approved DRAFT whose stamped `draftReadHash` matches its current normalized content
When `settle run` evaluates `draft-read` and the DRAFT's mtime is newer than `draftReadAt` (a touch, a re-checkout, or a re-save that only switched LF to CRLF or added a BOM)
Then:
- the gate passes without `--allow-stale-draft`;
- the gate writes exactly this to stderr, once: `settle: DRAFT.md mtime is newer than draftReadAt but its content is unchanged since approve; draft-read passes.\n`;
- nothing is written to stdout by the gate;
- the hash compared is of the same DRAFT text settle parsed for this run (one read, no re-read between parse and hash).

### AC-3: a real edit after approve still refuses, with today's message
Given an approved DRAFT with a stamped `draftReadHash`
When its content is changed after approve (its normalized hash now differs) and its mtime is newer than `draftReadAt`
Then:
- `settle run` refuses with the existing message, byte for byte: `settle run refused: DRAFT.md was edited after approve (mtime <iso> > draftReadAt <iso>). Re-read it then re-approve, or pass --allow-stale-draft to override.`;
- `--allow-stale-draft` still bypasses it, with the existing stderr notice unchanged.

### AC-4: legacy and unreadable cases fall back to today's mtime-only behavior
Given any of these:
- `draftReadHash` is `null` (state approved before this phase, or loaded from an older snapshot);
- a stamp exists, but the gate context cannot supply a content hash for this run (`draftContentHash()` returns `null`);

When `settle run` evaluates `draft-read` with a DRAFT mtime newer than `draftReadAt`
Then the gate refuses exactly as it does today (same message, same `--allow-stale-draft` bypass).
And the existing pass cases are unchanged: `draftReadAt` `null` passes; an unavailable mtime passes; an mtime not newer than `draftReadAt` passes without hashing anything.

### AC-5: docs describe the content check and the change ships with a changeset
Given the gate's behavior changed
When the operator reads `docs/concepts.md`'s gate table
Then the `draft-read` row describes a refusal on a content change since approve (mtime newer and normalized content hash differs), not a bare mtime check.
And a `.changeset/*.md` in this PR covers `@thomas-powers-jr/cadence-core` and `@thomas-powers-jr/cadence-types`.
