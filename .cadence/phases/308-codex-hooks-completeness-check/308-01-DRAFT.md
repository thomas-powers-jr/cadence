# 308-01 — codex hooks completeness check

## Objective

`cadence doctor`'s `checkCodexHooks` (packages/core/src/doctor/run.ts) still
reports `.codex/hooks.json` as fully managed on a single
`_managedBy: "cadence"` marker anywhere in the document — the same
existence-only gap phase 295 fixed for `checkHostHooks` (Claude Code). Give
`checkCodexHooks` the same completeness check: verify every hook entry
`host-codex`'s installer actually writes (`SessionStart`, `UserPromptSubmit`,
`PreToolUse`/`PostToolUse` matched on `^apply_patch$`, `Stop`,
`SubagentStop`) is present, not just that some single marker exists
somewhere. Move the expected-hook list into
`@thomas-powers-jr/cadence-host-toolkit` as the shared single source of
truth between the installer and the doctor check, mirroring phase 295's
`CLAUDE_CODE_EXPECTED_HOOKS` pattern, and pin the installer's and core's
independently-held copies against each other with a drift test.

## Acceptance Criteria

### AC-1: checkCodexHooks names every missing managed hook entry
Given `.codex/hooks.json` contains a `_managedBy: "cadence"` entry only on
`Stop` (the five other expected entries absent)
When `cadence doctor` runs
Then the `codex-hooks` check reports severity `error`, `fixId:
'codex-host-install'`, and its message names every expected entry absent
from the document (all five, for that fixture: `SessionStart`,
`UserPromptSubmit`, `PreToolUse` matcher `^apply_patch$`, `PostToolUse`
matcher `^apply_patch$`, `SubagentStop`)

### AC-2: checkCodexHooks reports ok only once the full set is present
Given `.codex/hooks.json` contains `_managedBy: "cadence"` entries for all
six expected (event, matcher) pairs
When `cadence doctor` runs
Then the `codex-hooks` check reports severity `ok`

### AC-3: installer and doctor check share one pinned source of truth
Given `@thomas-powers-jr/cadence-host-toolkit` exports a `CODEX_EXPECTED_HOOKS`
list that `host-codex`'s `install.ts` builds its `desired` hook map from, and
`packages/core/src/doctor/host-hooks.ts` holds its own independent copy (core
cannot import host-toolkit or any host-adapter package)
When the host-codex test suite runs
Then a drift test asserts the two lists describe the same six (event,
matcher) pairs, and separately pins those pairs against a hardcoded literal
list (not just against each other)
