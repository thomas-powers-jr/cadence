# 324-01 — bump mcp sdk, proxy-addr and source-map-js past audit advisories

## Objective

Make the required `security-success` check green again, by fixing rather than excepting (rec-20261007-001). Three high/critical advisories published after `main`'s last green Security run (2026-10-05) now fail `scripts/check-audit-exceptions.mjs` on every PR; PR #551 (phase 323, 2026-10-07, Security run 37700912102) was the first blocked. `main`'s branch protection requires `ci-success`, `security-success` and `codeql-success` (confirmed with `gh api …/branches/main/protection` on 2026-10-07), so this blocks every merge. Unlike phase 321's dev-only cases, two of the three reach the **published surface**: `@thomas-powers-jr/cadence-core` has a production dependency on `@modelcontextprotocol/sdk` (`^1.29.0`, resolving 1.30.0), which is itself affected (`GHSA-6qxp-vccf-f47h`, high, `>=1.12.0 <1.31.0`, OAuth client token leak) and which pulls `express@5.2.1` → `proxy-addr@2.0.7` (`GHSA-jqcg-44mw-7w3h`, **critical**, `>=1.1.0 <2.0.8`, IP spoofing via IPv4-mapped addresses). Core only uses the SDK's stdio transport, so express and the OAuth client are not reachable through CADENCE itself, but they ship in every consumer's install. The third, `source-map-js@1.2.1` (`GHSA-68fv-2mgg-jv7q`, high, `<1.2.2`, event-loop denial of service), is dev-only via `@vitest/coverage-v8` → `magicast` and `vite` → `postcss`. Patched releases exist for all three: `@modelcontextprotocol/sdk` 1.31.0 (the range resolves 1.32.1, whose dependency list is identical to 1.30.0's), `proxy-addr` 2.0.8 (express 5.2.1 declares `^2.0.7`, so a plain `pnpm install` keeps the locked 2.0.7; an override is needed to move it), `source-map-js` 1.2.2. The fix: raise core's SDK range to `^1.31.0`, add the range-keyed overrides `proxy-addr@<2.0.8` → `^2.0.8` and `source-map-js@<1.2.2` → `^1.2.2` in the pattern phases 253/297/321 established (a `<floor` source key cannot rot into a silent no-op once the tree moves), refresh `pnpm-lock.yaml`, and extend the real-state doc tests so the floors are pinned against the committed files. No exception row is added to `docs/security/audit-exceptions.md`. The overrides shape only this repository's lockfile; they do not propagate to consumers, whose fresh installs resolve `proxy-addr` 2.0.8 through express's `^2.0.7` and get the patched SDK through core's new range. Out of scope, deliberately: `@changesets/cli` 3.x (Dependabot #474, the `braces` exception's unblock), and the stale "only `ci-success` is required" wording in CLAUDE.md (three passages), `.claude/skills/pr-land/SKILL.md` and `docs/release.md`, which is filed as its own recommendation (rec-20261007-002) so this phase stays the smallest change that unblocks every merge.
