# 302-01 — doctor conduction-reachability: thread resolved packs into the profile-axis check

## Objective

`assessGateReachability`'s profile axis (`packages/core/src/doctor/run.ts`)
decides whether `code-review`/`security-audit` are "blocked by profile" by
checking raw `gatesFor(tier, profile).gates` at every `Tier` — never
consulting `config.packs`. `effectiveGateSet` (the single chokepoint pack
gate deltas are applied through, per `docs/packs-design.md` §4b/I-4) has
been packs-aware since Slice 3 (phase 292); this doctor check was left
behind only because Slice 3's own DRAFT boundary forbade touching
`doctor/run.ts`. A pack that adds `security-audit`/`code-review` via
`gates[].add` at a (profile, tier) cell absent from raw `DELTAS` therefore
makes this check report the gate as profile-blocked even though
`effectiveGateSet` now genuinely fires it once that pack is enabled — a
false negative in the doctor's own honesty tooling (`rec-20260823-001`).

**Scope note — not a design reversal.** `docs/packs-design.md` §4b locks two
things: `gatesFor` itself stays pure/pack-free, and pack *application*
happens at the single `effectiveGateSet` chokepoint (`dec-20260822-020`).
Neither is touched here. §4b's parenthetical describing
`assessGateReachability` as answering "a matrix-wide question independent
of any single phase's active packs" is a description of what the caller did
at the time, offered as the reason it could safely call a pure function —
not a decision that this check must forever under-report pack-augmented
reachability. The fix routes the caller through the existing
`effectiveGateSet` chokepoint (no new pack-matching logic invented in
`doctor/run.ts`) instead of calling `gatesFor` directly, mirroring the
precedent `config-explain/build.ts` already set in Slice 3 for its own
current-tier row. `gatesFor` itself is untouched.

**Gap is latent, not live.** `.cadence/packs/cadence/core-skills/pack.json`
(the only real pack manifest that exists today) declares no `gates` field —
no enabled pack currently adds a gate delta, so this repo's own `cadence
doctor` output does not change today. The fix closes a constructible,
independently-reproduced gap (any future pack declaring `gates[].add` at an
absent cell), not a live misreport happening right now — the ACs below use a
synthetic fixture pack, not `main`'s real one.

that pack in `resolvedPacks`
Then `security-audit` is reported reachable (not `blocked by profile`)

enabled pack declares any `gates[]`)

`checkConductionReachability` describe block still produces its original

`docs/packs-design.md` §4b gets an As-built note recording that
