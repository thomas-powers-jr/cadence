# 325-01 — phase 324's changeset test survives release consumption

## Objective

Phase 324's `324-01 / AC-4` tests in `packages/core/tests/docs/phase324-audit-advisories.test.ts` `readFileSync` the changeset `.changeset/audit-advisories-bump.md`. A release's `changeset version` step deletes consumed changesets, so the v1.69.1 cut (`release/v1.69.1`, local commit `2d20edf5`) failed `cadence-core#test` with ENOENT in both AC-4 tests and the release is blocked. Phase 303 fixed this bug class for two other tests with `tests/support/changeset-evidence.ts`; phase 324 did not use it. Make the AC-4 tests pass both before and after consumption without weakening them: while the changeset exists, assert against it exactly as today; once it is consumed, assert the same facts (only cadence-core is released, as a patch; the body names all three advisory ids, `^1.31.0` and the consumer-propagation caveat) against the published packages' `CHANGELOG.md` files, and fail when neither source carries the entry.

## Acceptance Criteria

### AC-1: a pure CHANGELOG-entry finder recovers a consumed changeset's change type and body
Given a new pure helper `findChangelogEntries(changelogText, discriminator)` in `packages/core/tests/support/changeset-evidence.ts`
When it is given changesets-generated `CHANGELOG.md` text (`## <version>` sections, `### Major Changes` / `### Minor Changes` / `### Patch Changes` subsections, `- <sha>: ` bullets whose continuation lines are indented) and a discriminator string
Then it returns every bullet entry containing the discriminator, each with its version, its change type (`major` | `minor` | `patch`, read from the enclosing `### … Changes` heading) and the full text of that one bullet, and returns an empty array when no entry contains it

### AC-2: phase 324's AC-4 tests pass before and after `changeset version` consumes the changeset
Given a pure helper `synthesizeConsumedChangeset(changelogs, discriminator)` in `changeset-evidence.ts` that, for a list of `{ packageName, text }`, returns `{ frontmatter, body, matchCount }` with one `"<packageName>": <change type>` frontmatter line per matching entry and the matching entries' text as the body; and the AC-4 describe block in `phase324-audit-advisories.test.ts` reading `{ frontmatter, body }` from `.changeset/audit-advisories-bump.md` while it exists, and otherwise from `synthesizeConsumedChangeset` over the five published packages' `CHANGELOG.md` files (package names read from each package's `package.json`), with the discriminator `Those overrides shape only this repository's lockfile and do not propagate to consumers`
When the two existing AC-4 assertions run unchanged (frontmatter equals exactly `['"@thomas-powers-jr/cadence-core": patch']`; body contains all three advisory ids, `^1.31.0` and `do not propagate to consumers`)
Then both pass on `main` today (changeset present) and on the v1.69.1 release tree (changeset deleted, `packages/core/CHANGELOG.md` carrying the entry under `## 1.69.1` / `### Patch Changes`); a unit test proves release-shaped core CHANGELOG text synthesizes exactly `['"@thomas-powers-jr/cadence-core": patch']`; and when the changeset is absent, an asserting test requires exactly one matching entry across the five CHANGELOGs

### AC-3: the fallback is not hollow
Given neither the changeset file nor any published package's `CHANGELOG.md` entry contains the discriminator
When the evidence is synthesized
Then unit tests prove `synthesizeConsumedChangeset` returns empty frontmatter and `matchCount` 0 (so the exact-equality AC-4 assertion would fail), and `findChangelogEntries` returns an empty array both for a discriminator absent from the text and for one that appears only in prose outside a `### … Changes` bullet
