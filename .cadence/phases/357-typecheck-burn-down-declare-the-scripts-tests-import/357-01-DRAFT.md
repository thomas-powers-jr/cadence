# 357-01 — typecheck burn-down: declare the scripts tests import

## Objective

Shrink core's test-typecheck baseline (phase 353) from 62 files to 48 (rec-20261127-001). Measured on 2026-11-27 with core's `tsconfig.test.json` and no exclusions, 14 baseline files share one cause: they import the repo-root modules `scripts/check-audit-exceptions.mjs`, `scripts/check-lockfile-overrides.mjs`, `scripts/publish-proof.mjs` and `scripts/release-integrity.mjs`, which have no type declarations (TS7016, 18 errors). Nine of them fail on nothing else; in five more, the untyped imports also leave callback parameters implicitly `any` (TS7006) and cause one downstream TS2339 at `tests/docs/phase260-vitest-v4-upgrade.test.ts:53`, and `tests/scripts/release-integrity.test.ts` also carries three TS2352 casts of a `spawnSync` test double. A scratch prototype with precise declarations (2026-11-27) left 4 errors in the batch: those three casts and one TS2345 at `tests/docs/check-lockfile-overrides.test.ts:362`. After this phase each of the four scripts has a hand-written `scripts/<name>.d.mts` declaration beside it, guarded by an export-name parity test, the residual errors in the 14 files are fixed in those files, and the 14 are gone from core's `exclude` and from the ratchet's `BASELINE`, whose cap drops from 62 to 48. The scripts' runtime code does not change.

Definitions used by AC-1 to AC-4. The four scripts: `check-audit-exceptions`, `check-lockfile-overrides`, `publish-proof`, `release-integrity` under `scripts/`. A script's exported names: the identifiers named by its lines starting `export function`, `export async function`, `export class` or `export const`, plus those listed in an `export { … }` line. A declaration's exported names: the identifiers on its lines starting `export function`, `export declare function`, `export class`, `export declare class`, `export const` or `export declare const`, plus those in an `export { … }` line (with or without `from`); `export interface` and `export type` lines are not counted. The batch: the 14 core test paths `tests/docs/check-lockfile-overrides.test.ts`, `tests/docs/lockfile-overrides-current-state.test.ts`, `tests/docs/phase260-vitest-v4-upgrade.test.ts`, `tests/docs/phase321-brace-advisories.test.ts`, `tests/docs/phase324-audit-advisories.test.ts`, `tests/docs/phase328-website-advisories.test.ts`, `tests/docs/phase329-changesets-3x.test.ts`, `tests/docs/phase330-root-moderate-advisories.test.ts`, `tests/docs/phase334-vite-high-advisory.test.ts`, `tests/docs/phase338-zod-body-parser-undici-advisories.test.ts`, `tests/docs/release-verify-budget.test.ts`, `tests/docs/security-ci.test.ts`, `tests/scripts/publish-proof.test.ts`, `tests/scripts/release-integrity.test.ts`.

## Acceptance Criteria

### AC-1: Each script's declaration names its exports
Given the four scripts and their `scripts/<name>.d.mts` files after this phase
When the parity test reads both files of a script
Then for `check-audit-exceptions`, `check-lockfile-overrides`, `publish-proof` and `release-integrity` the declaration's exported names equal the script's exported names; for example `publish-proof`'s set is `{ must, exerciseLoopSteps, withUnconditionalTeardown }`.
Not covered: exported interfaces and type aliases, which a declaration may add freely; whether a declared type matches the runtime behaviour, which the 14 tests' compile and run check only as far as they exercise it; scripts other than the four.

### AC-2: The batch leaves the baseline
Given core's `tsconfig.test.json` and the ratchet test's `BASELINE` after this phase

Not covered: the other 12 batch paths, which the 48-entry count and the empty problem list pin together (a batch path left in either list fails one of them); the compile itself, which `pnpm typecheck` runs in CI.

Not covered: phase 353's other three variations, which keep their shape with the 48-entry baseline.
