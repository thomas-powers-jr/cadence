# 300-01 — Guard settle's canonical SUMMARY overwrite on refusal

## Objective

`writeRefusedSettleSummary` (`packages/core/src/services/settle.ts`) writes a
refused settle attempt's record to the SAME canonical path as a successful
settle (`<draftId>-SUMMARY.json`/`.md`), unconditionally. Reproduced live
(`rec-20260915-002`, `ev-20260915-002`): a refused settle against stale state
clobbered an already-shipped draft's canonical SUMMARY, losing its AC PASS
results, gate provenance, contentHash, and stateAtSettle — recovered only
because the tree was dirty. Guard the canonical write so a refusal can never
overwrite an on-disk SUMMARY that already recorded real, terminal evidence
from a prior successful settle; divert that case to the existing
snapshot-sibling mechanism instead, with a loud stderr notice. The
refused-summary feature itself (recording refused attempts at all, and its
findings-gated snapshot sibling) is intentional (phase 239/247) and stays —
only the unconditional canonical overwrite becomes conditional.

## Acceptance Criteria

### AC-1: a refused settle does not clobber a terminal canonical SUMMARY
Given a draft's canonical `<draftId>-SUMMARY.json` on disk already has a
non-empty `acResults` array and a non-empty `gates` array (i.e. it recorded a
prior successful settle)
When a later `cadence settle run` for that same draft/state hits a refusal
Then the on-disk canonical `SUMMARY.json` and `.md` are byte-identical after
the refused attempt as they were before it — never overwritten

### AC-2: the refused attempt is still recorded, just not canonically
Given AC-1's guard has diverted a refused write away from the canonical path
When the refused settle attempt completes
Then a snapshot sibling is written to disk (via the existing
`refusedSnapshotArtifactBase` naming scheme) containing the full refused
record that would otherwise have been written canonically — unconditionally
in this diverted case, not gated on code-review/security-audit findings the
way the pre-existing findings-triggered sibling is

### AC-3: the diversion is loud, not silent
Given AC-1's guard fires
When the refused settle attempt completes
Then a stderr notice is emitted naming the guard and the diverted snapshot
path (matching this repo's convention that every fallback is loud, never
quiet)

### AC-4: the pre-existing behavior is unchanged when there is nothing terminal to protect
Given either no canonical SUMMARY exists yet for the draft, or an existing
canonical SUMMARY itself has `acResults: []` (e.g. it is itself a prior
refused record, not a prior successful settle — `gates` is non-empty on
refused records too and is NOT the discriminator; see T2)
When a settle attempt refuses
Then the canonical `SUMMARY.json`/`.md` is written exactly as it was before
this fix (the unconditional canonical write path is preserved for the
non-terminal case) — this is the phase-170/T4 and phase-247 existing test
coverage in `packages/core/tests/services/settle.test.ts`, which must keep
passing unmodified

### AC-5: full package test suite and typecheck pass
Given the fix and regression tests are in place
When `pnpm --filter @thomas-powers-jr/cadence-core test` and
`pnpm --filter @thomas-powers-jr/cadence-core typecheck` run
Then both exit successfully with no failures

### T2: Guard the canonical write in `writeRefusedSettleSummary`
- files: `packages/core/src/services/settle.ts`
- action: before the unconditional `atomicWriteJSON`/`atomicWriteText` calls
  at the canonical `refusedSummaryBase` path, best-effort read+parse the
  existing on-disk `${refusedSummaryBase}.json` (never throws on missing
  file or parse failure — absent/malformed means "nothing terminal to
  protect", falls through to the existing unconditional-write behavior).
  Guard predicate is **`acResults.length > 0` alone** — do NOT include
  `gates` in the predicate: `gates` is non-empty on every refused write too
  (the refusing gate's own result is merged into `acc.gates` before the
  refusal short-circuit, per the phase-247 comment at ~875-883, and
  `acResults` is hardcoded to `[]` on every refused write per line ~865), so
  a `gates`-inclusive predicate would incorrectly divert on the very next
  retry after the FIRST-EVER refusal too, breaking AC-4. When the predicate
  is true, divert this write to the snapshot-sibling path — call
  `refusedSnapshotArtifactBase(state.activeDraft!, refusedSummary.completedAt)`
  (reuse `refusedSummary.completedAt`, not a second `now()` call, matching
  the existing findings-triggered sibling's own reasoning at ~926-928 about
  clock drift) unconditionally in this branch, not gated on
  `hasCodeReviewFindings`/`hasSecurityAuditFindings` — and emit an `io.err`
  notice naming the guard and the diverted path. Otherwise (no existing
  file, parse failure, or existing file has `acResults: []`), keep the exact
  current unconditional canonical write
- verify: T1's regression tests now pass; canonical SUMMARY unchanged;
  snapshot sibling written with the full refused record; notice printed
- done: AC-2, AC-3

## Boundaries

- DO NOT touch the refused-summary FEATURE itself — `writeRefusedSettleSummary`
  continues to run on every refusal, and the existing findings-gated snapshot
  sibling logic (phase 247) is untouched except for the new unconditional
  divert-on-terminal-guard branch T2 adds.
- DO NOT change the `Summary` schema (`packages/types`).
- DO NOT touch the success path's canonical SUMMARY write
  (`finalizeAndCloseSettle`, `settle.ts` ~1132) — this phase is scoped to the
  refused-attempt path only.
- DO NOT attempt to fix or clear the primary checkout's stale phase-278
  `state.json` — that is a separate, explicitly operator-gated action
  (see `rec-20260915-002`'s own evidence trail) and out of scope here.
- DO NOT broaden this into a general "protect any canonical artifact"
  refactor — scope is exactly `writeRefusedSettleSummary`'s canonical write.
