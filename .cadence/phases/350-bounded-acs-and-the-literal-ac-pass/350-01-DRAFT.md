# 350-01 — Bounded ACs and the literal AC pass

## Objective

Make the two process changes that cut phase 348's settle to zero surprise failures (rec-20261121-005; phase 347 needed six Codex rounds, phase 348's literal pass predicted both of its real settle failures before the first Codex run) part of how CADENCE builds itself, and give the first of them a mechanical layer: `cadence draft check` warns when an AC's Then-text promises a universal ("any", "every", "each", "same", "unchanged") that a hostile settle-time verifier can always find one more corner under; the phase-build skill requires a literal DRAFT review and a literal clause-by-clause AC pass before the first settle run, which is a `--dry-run`; CLAUDE.md's DRAFT section tells authors how to write a bounded AC; and the `bugfix` and `refactor` DRAFT templates stop tripping the new warning.

Definitions used by AC-1 and AC-2. The Then-text is the parsed `then` field of an AC. A word is a maximal run of ASCII letters; every other character, including `-`, `'` and the backtick, separates words. A stop line is a line whose text, after leading spaces and tabs are removed, begins with `Not covered:` compared case-insensitively; the scan reads the Then-text only up to the first stop line. A universal word is one of `any`, `every`, `each`, `same`, `unchanged`, matched case-insensitively against whole words.

## Acceptance Criteria

### AC-1: Coherence warns with an exact message for a universal word in the Then-text
Given `coherenceCheck(draft, state, '')` where the state has no decisions and the draft has no tasks and a single AC, AC-2, and the three examples (a) Then-text `Every row stays unchanged`, expected message `AC-2's Then-text uses universal word(s) "every", "unchanged"; bound it with named example inputs and outputs, or move the boundary to a "Not covered:" line.`; (b) Then-text `Each row`, expected message `AC-2's Then-text uses universal word(s) "each"; bound it with named example inputs and outputs, or move the boundary to a "Not covered:" line.`; (c) Then-text `same-day rows`, expected message `AC-2's Then-text uses universal word(s) "same"; bound it with named example inputs and outputs, or move the boundary to a "Not covered:" line.`
When it runs on example (a), (b) and (c) in turn
Then its `issues` array equals `[{ severity: 'warn', code: 'UNBOUNDED_AC_THEN', message: <that example's expected message> }]` in all three runs, and the exported constant `UNIVERSAL_AC_WORDS` equals the five universal words of the Objective's definitions, in that order.
Not covered: an AC whose heading or Given contains a capitalised `Then ` (the parser's Then capture is unanchored, so the scan starts there; tracked separately); trailing prose after the last AC in a section, which the parser folds into that AC's Then-text; escalation to `block`.

### AC-2: Bounded Then-texts do not warn
Given `coherenceCheck(draft, state, '')` with no decisions and no tasks, and a draft with four ACs whose Then-texts are (AC-1) `the row reads hooksObserved: false` then a new line `Not covered: every other row`; (AC-2) `the tally counts anything recorded and its sameness`; (AC-3) `the row is kept` then a new line `  not covered: each row`; (AC-4) `the message names T1, T2`
When it runs
Then its `issues` array is `[]`.
Not covered: a stop line written as `- Not covered:` or `**Not covered:**`, which does not stop the scan; Given and When text.

### AC-3: The bugfix and refactor templates produce no UNBOUNDED_AC_THEN warning
Given the DRAFTs that `draft new --template bugfix`, `--template feature` and `--template refactor` generate for the title `widget`
When each is parsed and passed to `coherenceCheck` with no decisions and an empty PROJECT.md
Then none of the three results contains an issue with code `UNBOUNDED_AC_THEN`.
Not covered: the untemplated scaffold, whose Then line is a placeholder; DRAFTs authors write.

### AC-4: The phase-build skill names both literal passes and a dry-run first settle

## Boundaries

- Do NOT make `UNBOUNDED_AC_THEN` a `block`; it is a warning only, and `draft approve` must still approve a DRAFT that has it.
- Do NOT change the DRAFT parser (`packages/core/src/parse/draft-parser.ts`), `AcceptanceCriterionZ` or any schema; the `Not covered:` line stays part of the Then-text and only the coherence scan treats it specially. The unanchored Then capture is tracked as its own recommendation.
- Do NOT add a config knob for the word list.
- Do NOT renumber the phase-build skill's steps or edit the step 7 / step 8 heading text.
- Do NOT edit CLAUDE.md's version line or any section other than `### The loop and its artifacts`.
- Do NOT change a template's AC headings; only the two named Then lines.
- Do NOT add a runtime dependency.
