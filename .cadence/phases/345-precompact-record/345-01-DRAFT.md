# 345-01 — PreCompact writes a record-only machine-facts handoff

## Objective

Nothing in cadence reacts to compaction today: no adapter installs `PreCompact`, so when Claude Code compacts a session (by `/compact` or automatically) the agent's position is lost with no record unless the checkpoint Stop gate happened to fire first (rec-20261101-001, ev-20261101-001/-003). This phase maps Claude Code's `PreCompact` hook to a new `pre-compact` abstract event whose core handler writes a separate, machine-facts-only record, `.cadence/local/precompact/PRECOMPACT-<timestamp>.md` (under the already-gitignored `.cadence/local/`), carrying the compaction trigger (`auto` or `manual`, recorded verbatim but JSON-quoted) and the host payload's field names (never their values). The event never blocks compaction: core always exits 0 for it, and the Claude Code shim clamps a non-zero core exit to 0 for this event so a newer adapter running against an older core cannot block a compaction. The handler never writes stdout and never modifies `state.json` or any `SESSION-*.md` doc. The SessionStart banner and `cadence resume` point at the newest record when it is newer than the freshest SESSION doc. Claude Code only: the Codex adapter keeps `PreCompact` unmapped. Operator decisions recorded before drafting: phase number 345 (344 stays reserved for verifier isolation, rec-20261030-010), a separate record rather than a SESSION doc, and Claude Code only. The records live under `.cadence/local/`, which `cadence init` has gitignored since phase 341, so a record never dirties the tree for the next one and no new gitignore entry is needed (independent DRAFT review findings I7 and N1-N3); projects initialized before phase 341 lack that entry, a known limitation the changeset states. A side effect, not a goal: every record of a real auto-compaction is evidence for rec-20261101-002 (gap M10).

## Acceptance Criteria

### AC-1: Claude Code PreCompact reaches core as pre-compact with its trigger; Codex stays unmapped
Given a Claude-Code-shaped hook stdin `{ "hook_event_name": "PreCompact", "trigger": "auto", ... }`
When host-toolkit's `routeHookEvent` translates it and core's `cadence hook pre-compact` reads the translated stdin
Then the abstract event is `pre-compact`; the translated stdin carries `compactTrigger: "auto"` (any string trigger is passed through unchanged; a missing or non-string trigger yields no `compactTrigger` key); core's hook command copies a string `compactTrigger` into the `HookContext`; `AbstractEventZ` accepts `pre-compact` and `HookContextZ` accepts an optional `compactTrigger` string; and `packages/host-codex`'s `mapEvent('PreCompact')` still returns `null`.

### AC-2: The Claude Code installer writes a PreCompact hook and doctor expects it
Given a project with a `.claude/` workspace
When the Claude Code host install runs
Then `.claude/settings.json` gains a managed `PreCompact` entry (no matcher) beside the existing managed entries; `CLAUDE_CODE_EXPECTED_HOOKS` in host-toolkit and its independent copy in `packages/core/src/doctor/host-hooks.ts` both list it and the drift test passes; `claudeCodeCapabilities.hooks` lists `pre-compact` and `blockingHooks` does not; and `cadence doctor` run against a settings file written before this phase reports the missing `PreCompact` hook through its existing missing-hook path (fixable with `cadence doctor --fix --wire-host`).

### AC-3: pre-compact writes one machine-facts record under .cadence/local/ and touches nothing else
Given a project whose `.cadence/` directory exists, at any loop position, with or without an existing `.cadence/local/precompact/` directory
When `cadence hook pre-compact` runs
Then `.cadence/local/precompact/` exists (created if missing, never creating `.cadence/` itself) and exactly one new file `.cadence/local/precompact/PRECOMPACT-<YYYYMMDDTHHMMSS.mmmZ>.md` exists (a same-millisecond collision gets a `-2`, `-3` suffix and never overwrites); its front matter carries `generated_at` (ISO), `trigger` as a JSON-quoted string (`"unknown"` when absent), loop position, active phase, active draft and active spec; its body lists the host payload's top-level field names only, excluding the adapter-added keys `compactTrigger`, `files`, `skill`, `agentId` and `agentType`, and never any value (so `custom_instructions` and `transcript_path` are never copied); git facts (branch, HEAD, dirty, ahead/behind from local refs only, no fetch) are included when available and marked unavailable otherwise; `CADENCE_OWNED_GITIGNORE_ENTRIES` is unchanged; and `state.json`, `STATE.md`, every `SESSION-*.md` doc and every `.cadence/intelligence/` file are byte-identical before and after.

### AC-4: pre-compact always exits 0 with empty stdout and one stderr line
Given the default logger configuration and any of: success; `state.json` missing or corrupt; `config.json` invalid; no `.cadence/` directory at the hook's working directory; an unwritable record directory; git absent or not a repository; stdin that is not valid JSON or cannot be read
When `cadence hook pre-compact` runs
Then the process exits 0, stdout is empty, and stderr carries exactly one line, naming the record's path on success or the cause otherwise; when state cannot be read but `.cadence/` exists the record is still written with loop fields marked `unavailable`; when `.cadence/` does not exist nothing is created and the stderr line says so; and `renderHookResult('pre-compact', …)` returns exit code 0 for every result, including `{ ok: false }`.

### AC-5: Records are pruned to the newest five, silently and safely
Given `.cadence/local/precompact/` holds more than five `PRECOMPACT-*.md` records
When a new record is written
Then records beyond the newest five (ordered by file name) are deleted; no other file in that directory, no `SESSION-*.md` doc and nothing else under `.cadence/` is touched; pruning writes nothing to stdout or stderr; and a prune failure does not fail the write.

### AC-6: A newer adapter running against an older core cannot block a compaction
Given the Claude Code shim routes a `PreCompact` event and the core child process exits non-zero (for example exit 2 with `Unknown hook event: pre-compact` from a core that predates this phase)
When the shim finishes
Then the shim exits 0 and writes one stderr line naming the core exit code; a spawn failure or other shim error on a `pre-compact` event also exits 0 with one stderr line; every other event's exit-code handling is unchanged.

### AC-7: The SessionStart banner and resume point at a newer record, and are otherwise unchanged
Given the newest `PRECOMPACT-*.md` record's `generated_at` is later than the freshest SESSION doc's `generated_at` (a SESSION doc with no `generated_at` counts as the end of its file-name date; any record counts as newer when no SESSION doc exists)
When the SessionStart hook runs, or `cadence resume` runs without `--list` or `--pick`
Then the banner ends with one extra line naming the record's path, trigger and time; `cadence resume` prints the same pointer line before the replayed narrative, or after its "no handoff found" line when there is no SESSION doc; `cadence resume --json` (and the MCP `cadence_resume` tool, which returns the same result) carries an optional `precompactRecord` object `{ path, trigger, generatedAt }` on both branches of `ResumeResultZ`; when no record is newer, the banner and every resume output are byte-identical to the current output; `--list` and `--pick` are unchanged; and a lookup failure contributes nothing.

### AC-8: The event, the record and its limits are documented
Given the doc-content test suite
When it runs
Then `docs/reference/commands.md` (a hook-events list outside the `<!-- cadence:commands -->` marker block), `docs/claude-code.md` (its event table, including the missing `SubagentStart` row and a corrected count) and `docs/host-adapters.md` name `pre-compact` and describe the record's path and contents, its location under the gitignored `.cadence/local/`, five-record retention, the never-blocks rule, the shim exit clamp, and the Claude-Code-only scope; a doc-content test asserts the documented hook-events list equals `AbstractEventZ`'s options; the `.cadence/local/` row of `docs/concepts.md`'s State files table lists `precompact/`; and a changeset records the change with an upgrade note that existing installs see a doctor `host-hooks` error until `cadence doctor --fix --wire-host` runs, and that projects initialized before phase 341 should add `.cadence/local/` to `.gitignore`.

## Boundaries

- Do NOT make `pre-compact` blocking, and do NOT add it to any `blockingHooks` list. Blocking an auto compaction is rec-20261101-002 (needs-evidence) and is out of scope.
- Do NOT write, stamp or modify `state.json`, `STATE.md`, `state.session.lastHandoff`, any `SESSION-*.md` doc, or any `.cadence/intelligence/` file from the hook.
- Do NOT copy any payload value other than `trigger` into the record (`custom_instructions` may hold user text; `transcript_path` is machine-absolute).
- Do NOT map PreCompact or PostCompact in `packages/host-codex`, and do NOT map PostCompact anywhere.
- Do NOT touch `packages/checkpoint/`.
- Do NOT put record logic in host-toolkit or host-claude-code. The adapters translate the event, extract and forward `trigger`, and the Claude Code shim clamps the `pre-compact` exit code; that is all.
- Do NOT change the shim's exit-code handling for any event other than `pre-compact`.
- Do NOT change `CADENCE_OWNED_GITIGNORE_ENTRIES` or this repo's `.gitignore`; the records live under the already-ignored `.cadence/local/`.
- Do NOT create `.cadence/` from the hook; write only when it already exists.
- Do NOT run `git fetch` or any network call from the hook.
- Do NOT add a runtime dependency.
- Do NOT change the gate matrix in `packages/core/src/gates/engine.ts`; in `docs/concepts.md` edit only the `.cadence/local/` row of the State files table.
- Do NOT edit inside the `<!-- cadence:commands -->` marker block of `docs/reference/commands.md` by hand.
