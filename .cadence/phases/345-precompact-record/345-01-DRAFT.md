# 345-01 — PreCompact writes a record-only machine-facts handoff

## Objective

Nothing in cadence reacts to compaction today: no adapter installs `PreCompact`, so when Claude Code compacts a session (by `/compact` or automatically) the agent's position is lost with no record unless the checkpoint Stop gate happened to fire first (rec-20261101-001, ev-20261101-001/-003). This phase maps Claude Code's `PreCompact` hook to a new `pre-compact` abstract event whose core handler writes a separate, machine-facts-only record, `.cadence/handoff/PRECOMPACT-<timestamp>.md`, carrying the compaction trigger (`auto` or `manual`, recorded verbatim) and the payload's field names (never their values). The handler never blocks, never writes stdout, never modifies `state.json` or any `SESSION-*.md` doc, and degrades to one stderr notice on any failure. The SessionStart banner and `cadence resume` point at the newest record when it is newer than the freshest SESSION doc. Claude Code only: the Codex adapter keeps `PreCompact` unmapped. Operator decisions recorded before drafting: phase number 345 (344 stays reserved for verifier isolation, rec-20261030-010), a separate record rather than a SESSION doc, and Claude Code only. A side effect, not a goal: every record of a real auto-compaction is evidence for rec-20261101-002 (gap M10).

## Acceptance Criteria

### AC-1: Claude Code PreCompact routes to pre-compact with its trigger; Codex stays unmapped
Given a Claude-Code-shaped hook stdin `{ "hook_event_name": "PreCompact", "trigger": "auto", ... }`
When host-toolkit's `routeHookEvent` (and therefore host-claude-code's shim) translates it
Then the abstract event is `pre-compact`, the extracted payload carries `compactTrigger: "auto"` (any string trigger is passed through verbatim; a missing or non-string trigger yields no `compactTrigger` key), `AbstractEventZ` accepts `pre-compact`, `HookContextZ` accepts an optional `compactTrigger` string, and `packages/host-codex`'s `mapEvent('PreCompact')` still returns `null`.

### AC-2: The Claude Code installer writes a PreCompact hook and doctor expects it
Given a project with a `.claude/` workspace
When the Claude Code host install runs
Then `.claude/settings.json` gains a managed `PreCompact` entry (no matcher) beside the existing managed entries, `CLAUDE_CODE_EXPECTED_HOOKS` in host-toolkit and its independent copy in `packages/core/src/doctor/host-hooks.ts` both list it (the existing drift test passes), `claudeCodeCapabilities.hooks` lists `pre-compact` and `blockingHooks` does not, and `cadence doctor` run against a settings file written before this phase reports the missing `PreCompact` hook through its existing missing-hook path.

### AC-3: pre-compact writes a machine-facts record and touches nothing else
Given an initialized project at any loop position
When `cadence hook pre-compact` runs with a `compactTrigger`
Then exactly one new file `.cadence/handoff/PRECOMPACT-<UTC timestamp>.md` exists, containing front matter and body with: generation time, trigger (verbatim, or `unknown` when absent), the raw payload's top-level field names only (never values, so `custom_instructions` text is never copied), loop position, active phase, active draft, active spec, and best-effort git facts (branch, HEAD, dirty, ahead/behind from local refs only, no fetch); and `state.json`, `STATE.md`, every `SESSION-*.md` doc and every ledger file are byte-identical before and after.

### AC-4: pre-compact never blocks, never writes stdout, and fails soft
Given any failure while writing the record (unwritable or missing `.cadence/handoff/`, git absent or not a repo, a malformed raw payload)
When `cadence hook pre-compact` runs
Then the process exits 0, the HookResult is `ok: true` with no `blockMessage`, stdout is empty, and stderr carries exactly one line naming the failure; in the success case stdout is also empty and stderr carries one line naming the record's path.

### AC-5: Records are pruned to the newest five, untracked only
Given `.cadence/handoff/` holds more than five `PRECOMPACT-*.md` records, some of them git-tracked
When a new record is written
Then untracked `PRECOMPACT-*.md` records beyond the newest five (by the timestamp in the file name) are deleted, no git-tracked record is deleted, no `SESSION-*.md` doc or other file is touched, and a prune failure does not fail the write.

### AC-6: The SessionStart banner and resume point at a newer record, and are otherwise unchanged
Given the newest `PRECOMPACT-*.md` record is newer than the freshest SESSION doc (by `generated_at`; any record counts as newer when no SESSION doc exists)
When the SessionStart hook runs, or `cadence resume` runs
Then the banner ends with one extra line naming the record's path, its trigger and its time, and `cadence resume` prints the same pointer line before the replayed narrative (and, with `--json`, a `precompactRecord` object carrying path, trigger and generatedAt); when no record is newer, the banner and the resume output (text and JSON) are byte-identical to the current output; a lookup failure contributes nothing.

### AC-7: The event, the record and its limits are documented
Given the docs-content test suite
When it runs
Then `docs/reference/commands.md` (the `cadence hook` events) and the host-adapter/hooks documentation name `pre-compact`, the record's path and contents, the five-record retention, the never-blocks rule and the Claude-Code-only scope; a doc-content test asserts the documented event list equals `AbstractEventZ`'s options; and a changeset bumps core, types, host-toolkit and host-claude-code by minor.

## Boundaries

- Do NOT make `pre-compact` blocking, and do NOT add it to any `blockingHooks` list. Blocking an auto compaction is rec-20261101-002 (needs-evidence) and is out of scope.
- Do NOT write, stamp or modify `state.json`, `STATE.md`, `state.session.lastHandoff`, any `SESSION-*.md` doc, or any `.cadence/intelligence/` ledger file from the hook.
- Do NOT copy any payload value other than `trigger` into the record (`custom_instructions` may hold user text; `transcript_path` is machine-absolute).
- Do NOT map PreCompact or PostCompact in `packages/host-codex`, and do NOT map PostCompact anywhere.
- Do NOT touch `packages/checkpoint/` (its Stop gate and session-start reset stay as they are).
- Do NOT put record logic in host-toolkit or host-claude-code; adapters only translate the event and extract `trigger`.
- Do NOT run `git fetch` or any network call from the hook.
- Do NOT add a runtime dependency.
- Do NOT change the gate matrix in `packages/core/src/gates/engine.ts`.
