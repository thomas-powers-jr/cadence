# 343-01 — verification.fallback: "refuse" turns a silent mock downgrade into a gate refusal

## Objective

Today every verifier seam that cannot reach its configured real provider prints a loud notice and quietly continues on mock. This covers a host-cli binary that will not launch, the claude self-invocation guard, a timeout, a missing Anthropic key, an unset local endpoint, and a family with no host-cli builder. An automated consumer of cadence-core can therefore settle on a mock by accident; Cadence Studio defends against that with a sentence in its CLAUDE.md, which is shape, not a gate (rec-20261030-004). This phase adds an additive config setting `verification.fallback: "mock" | "refuse"`. When it is absent or `"mock"`, behaviour is byte-identical to 1.73.0. Under `"refuse"`, `createVerifierFactory` (`packages/core/src/verify/verifier-factory.ts`), the one chokepoint every seam's downgrade goes through, never delegates to mock. Instead the verifier call throws a typed error naming the seam and the cause, and each consuming gate's existing verifier-failure path turns that into a refusal. Settle then exits non-zero, as on any other gate refusal. `doctor` reports the setting. A provider explicitly configured as `mock` is a choice, not a fallback, and is unaffected.

## Acceptance Criteria

### AC-1: An unlaunchable host-cli binary refuses settle under "refuse"
Given `verification.fallback: "refuse"`, `verifier.provider: "host-cli"`, and `CADENCE_HOST_CLI_BIN` naming a binary that does not exist
When `cadence settle run --auto --deep` runs on a draft whose tasks are all DONE
Then settle exits non-zero with a deep-verify refusal whose reason names the deep-verify seam, says fallback is refuse, and carries the host-cli cause; no `<id>-SUMMARY.json` is written, so no `strong` or `mixed` grade exists for the slice; and no "falling back to mock provider" notice is printed

### AC-2: The claude self-invocation guard refuses under "refuse" (the Studio case)
Given `verification.fallback: "refuse"`, a host-cli seam whose bin resolves to the claude family, and `CLAUDECODE=1` in the environment
When that seam's verifier is called
Then the call throws the same typed refusal, naming the seam and the self-invocation cause, without spawning a process and without calling the mock; and the code-review gate turns it into a refusal unless `--allow-code-review-failure` / `--force` is passed, in which case the existing `reviewVerifierFailure` bypass record applies unchanged

### AC-3: "mock" or unset is byte-identical to 1.73.0
Given `verification.fallback` absent, or set to `"mock"`
When each downgrade path runs — host-cli `HostCliError` at call time, anthropic with no key, local with no endpoint, and a family with no host-cli builder
Then the same mock delegate is called, the same warning text is emitted, and the same `providerSelection` tag (`fallback`) is applied as on 1.73.0, and `defaultConfig` and a fresh `cadence init` config are unchanged (the key is not written)

### AC-4: A launching binary is unaffected by "refuse"
Given `verification.fallback: "refuse"` and a host-cli seam whose binary launches and returns a valid verdict
When the seam's verifier is called
Then the result comes from the host-cli primary, is tagged `configured`, and no warning or refusal is emitted; and a seam whose configured provider is `mock` still returns the mock (an explicit choice is not a fallback)

### AC-5: The selection-time downgrades refuse lazily under "refuse"
Given `verification.fallback: "refuse"` and a seam configured for `anthropic` with no `ANTHROPIC_API_KEY`, or for `local` with no endpoint
When the verifier is selected and then not called, and separately when it is called
Then selection alone neither throws nor warns, so a gate that does not run cannot refuse; and the first call throws the typed refusal naming the seam and the missing prerequisite

### AC-6: doctor and the config reference report the setting
Given a repo config with `verification.fallback` set, or absent
When `cadence doctor --json` runs, and when `docs/reference/config.md` is read
Then doctor's JSON carries a check reporting the effective fallback (`mock` or `refuse`), and the config reference documents `verification.fallback`, its values, its default, and which seams it governs, with the doc-content test pair asserting both

## Boundaries

- Do NOT make `"refuse"` the default, and do NOT write the key into `defaultConfig` or a fresh init (D-B, dec-20260808-002); the default-flip is filed as a rec, not built.
- Do NOT change which gates the matrix fires (`gates/engine.ts`, `docs/concepts.md`).
- Do NOT touch the mock provider's identity, its abstention behaviour, or `ProviderSelectionTag`'s values (D-A, dec-20260808-001; decision (b) above).
- Do NOT change any warning text, tag, or delegate on the `"mock"`/absent path (AC-3).
- Do NOT add a new CLI flag; the setting is config-only. Existing `--allow-*-failure` / `--force` bypasses keep their meaning.
- Do NOT add a runtime dependency, and do NOT touch host adapters (`packages/host-*`).
- Tests use injected fakes and non-existent binary paths only; no real `claude`/`codex` spawn and no network.
