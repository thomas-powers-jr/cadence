boundary-scan names its diff base (phase 351; rec-20261125-001). The settle-time `boundary-scan` gate no longer falls back to the local integration ref in silence. It retries the merge-base of `origin/<integrationRef>` and `HEAD` once on an empty answer. When the remote-tracking ref does not resolve, it still diffs against the merge-base with the local ref and prints `boundary-scan: origin/<ref> did not resolve; diffing against the merge-base with the local <ref> ref (<sha>)` on stderr. When the remote-tracking ref resolves but its merge-base still cannot be computed, the gate refuses with a reason that names a shallow clone when that is the cause and suggests `git fetch --unshallow origin`; an unsealed `--allow-boundary-scan-failure` or `--force` proceeds with the working-tree scan only, prints a line naming the flag, and marks the result as bypassed. The `could not resolve a base ref` notice is now printed only when neither ref yields a merge-base. `build task`'s record-time check treats the new refusal case as an unresolved base, and the `deep-verify` diff keeps its own resolution order. Boundary-scan bypasses are still not recorded in the SUMMARY's `gateBypasses` (rec-20261125-002).
