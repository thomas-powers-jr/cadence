Skill-audit names unobserved host hooks (phase 349; rec-20261117-001). A session whose host hooks never fire, for example one started in a parent folder of the repository so `.claude/settings.json` or `.codex/hooks.json` is never loaded, records no skill invocations, and settle's skill-audit miss used to read as if the agent skipped the skill. The hook dispatcher now stamps the new optional `state.session.lastHookEventAt` after every event it handles except `pre-compact`, whatever the telemetry settings, through a revision-exempt write that re-reads `state.json` and is throttled to about once a minute; `cadence state load` clears it. A stamp no more than 30 minutes old counts as live. `cadence build task` (and `cadence done` and the MCP `cadence_build_task` tool) writes `hooksObserved: true | false` on the task's PROGRESS.json row and, when it is false and a CADENCE-managed hook entry is installed, prints one stderr notice naming the installed host config path(s); `cadence block`, `cadence needs-context` and older rows carry no key, which counts as observed. `cadence doctor` gains a `host-hooks-liveness` check that warns during BUILD when hooks are installed but none fired recently, and never errors. Settle's skill-audit refusal line, its `--dry-run` refusal reason and the `--allow-skill-audit-miss` bypass reason now name the tasks recorded with `hooksObserved: false`. The skill-audit requirement, its refusal and `--allow-skill-audit-miss` are unchanged, and a `state.json` without the new key still parses.
