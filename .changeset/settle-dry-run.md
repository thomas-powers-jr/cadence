`cadence settle run --dry-run` shows what settle would decide without settling (phase 347; rec-20261113-001). Until now settle was the only way to run the real code-review and deep-verify gates, and every failing code-review run spent one of the draft's convergence attempts (`convergence.maxAttempts`, default 3) in its `CODE-REVIEW.json` sidecar. A dry run runs settle's preconditions, resolves the same gate set and runs the same gates in the same order with the same diff basis, prompts, providers, `verification.fallback` and bypass flags; it stops at the first refusal as settle does, and with no gate refusal also runs AC derivation, the anomaly and skill-audit checks and the evidence floor, then stops before finalize. Cadence writes nothing and notifies nothing: no SUMMARY or refused-attempt snapshot, no RETRO, no code-review sidecar write (so it spends no convergence attempt), no `state.json`/`STATE.md`, PROGRESS or ledger change, no anomaly-log entry, and no anomaly event to any notifier transport, stderr included. The configured test command and any spawned review-agent process still run, and their own writes are outside this guarantee. The stdout report lists each gate's outcome and provider, deep-verify's per-AC verdicts, code-review and security-audit findings, code-review's `would be attempt N of M` and would-be convergence verdict (a passing or abstained review consumes no attempt), the events settle would send under `would notify:`, a note on its own line when settle would prompt (the verdict then assumes every AC is confirmed), and a final `settle would pass` or `settle would refuse at <gate or check>: <reason>` line. A dry run never prompts: where settle would walk ACs interactively it takes the non-interactive path and says so (under `CADENCE_REQUIRE_TTY=1` with no TTY it refuses at `interactive-verdict`, as settle does). It exits 0 if settle would pass, 1 if it would refuse, and 2 when combined with `--interactive` or `--ship-ref`, which are refused before anything runs. `settle run` without `--dry-run` is unchanged.
