New `cadence state save | load | list` carries the loop position between machines through committed snapshots (phase 341; dec-20261029-001). `.cadence/state.json` is gitignored, so it never traveled with a branch. `cadence state save` writes `.cadence/snapshots/state-<stamp>-<host>.json` and keeps the newest 3; commit it alongside a handoff, pull on the other machine, and run `cadence state load` (the newest snapshot by default, or a named one). `load` treats the snapshot as untrusted and refuses, changing nothing, when a path field is not a plain identifier (never overridable), when the snapshot has state keys this cadence does not know, when it belongs to another project, when its active phase directory is missing on this branch, or when this machine has local work since its last save or load. `--force` skips only the unknown-keys and local-work checks. A successful load keeps progress (including the active task and `draftReadHash`), resets the session's token and subagent counters, moves `revision` past both sides, re-renders `STATE.md`, and backs up the replaced `state.json` to `.cadence/local/state.json.bak`. `cadence state list` shows snapshots newest first, and all three subcommands take `--json`. `cadence init` and `cadence doctor` now also treat `.cadence/local/` as a CADENCE-owned gitignored path; `.cadence/snapshots/` stays committed. `cadence resume` is unchanged and still read-only. The types package exports the new `StateSnapshotZ` schema.
