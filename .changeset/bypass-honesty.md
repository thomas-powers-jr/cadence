Bypassing a failing test suite or real coverage gaps at settle now leaves a durable record (phase 346; rec-20260806-006, rec-20260726-005; dec-20261112-001, dec-20261112-002). Until now, `cadence settle run --allow-failing-build` or `--force` over a failing `verification.testCommand` wrote nothing to stderr, the test runner discarded the suite's output, and the bypass reached `SUMMARY.json` only as a skipped `gates[]` entry, never in `gateBypasses`, so such a settle could grade `assurance.overall: 'strong'`. Now the test runner keeps a bounded tail of a failing run's combined output (the last 40 lines, capped at 8 KiB, ANSI escape codes stripped, CRLF folded to LF); the pass or fail verdict is still the exit code alone. On a bypass the `build-test-must-pass` gate prints one stderr notice naming the flag that fired, the command, its exit code and the tail, and settle records one `error`-severity `gateBypasses` entry (`gate: "build-test-must-pass"`, that flag, `reason` `"<command> exited <code>"`, and a new optional `detail` field saying how many tail lines the notice showed; the tail itself is never recorded), which caps the grade at `mixed`. `SUMMARY.md` and `cadence summary render` show `detail` as an indented block; a SUMMARY with no `detail` renders byte-identically, so existing summary hashes do not change. Every refusal, sealed or not, also prints the tail after its existing stderr lines (a silent run prints `output tail: (no output captured)`). The command is redacted wherever it is printed or recorded: the value of every inline assignment (so `NODE_ENV=test pnpm test` shows as `NODE_ENV=[REDACTED] pnpm test`), URL userinfo, and credential flag values never reach a notice, an anomaly or the SUMMARY. A new `build-test-bypassed` anomaly (`error`) carries only the flag, the redacted command and the exit code: the tail never enters an anomaly event, so no notifier transport, including `webhook`, receives test output. Separately, in `assertion` coverage mode a bare `--force` that lets real coverage gaps through `test-coverage` is now recorded as a `warn` `test-coverage` bypass whose flag is `--force`, as `--allow-missing-coverage` already was. The types package gains the optional `GateBypassZ.detail` field and the `build-test-bypassed` anomaly type; existing SUMMARY records and anomaly logs keep parsing.

Upgrade notes:

- A settle that bypasses a failing test suite with `--allow-failing-build` or `--force` now grades at most `mixed`, never `strong`.
- The output tail is shown on stderr only and is never written into the committed `SUMMARY.json` or `SUMMARY.md`, because test output can contain secrets. The tail on stderr is still redacted: the values of secret-named environment variables and command assignments wherever they appear, URL userinfo, upper-case `NAME=value` pairs, quoted password keys, and the `redactSecrets` patterns used for SUMMARY findings. Redaction cannot know every secret, which is why the tail is not recorded.
- A bare `--force` over coverage gaps in `assertion` mode now adds a `warn` entry to `gateBypasses`. Automation that expects no `gateBypasses` on such a settle should pass real coverage instead.
