Host-cli review agents are spawned with isolation flags, and the flags are recorded on the gate entry (phase 344; rec-20261030-010). A codex-family binary is now run as `codex exec --json --skip-git-repo-check --ignore-user-config -` and a claude-family binary as `claude -p --output-format json --setting-sources project --strict-mcp-config`, so part of the user-level configuration is kept out of a review. The claim is narrow: these flags are passed and recorded. The global `AGENTS.md` (codex) and the global `CLAUDE.md` (claude) still reach the reviewer, and so do project-level instruction files and hooks, because the child runs in the project directory. The new optional config key `verification.hostCliIsolation` takes `"on"` or `"off"`; absent means `"on"`, and `cadence init` does not write it. Under `"off"` the review agents are spawned as before. The SUMMARY's `deep-verify`, `code-review` and `security-audit` gate entries carry a new optional `hostCliIsolation` field listing the flags that were passed; it is absent when isolation was off, the provider was not `host-cli`, the call fell back to mock, or no child was spawned. `cadence doctor` has a new `host-cli-isolation` check that names the flags the configured binary gets and the global instruction file that still reaches the reviewer, and warns under `"off"` when a seam uses `host-cli`. A CLI that rejects a flag fails the call without a retry, and the failure message carries a hint naming the flag and the setting.

Upgrade notes: host-cli reviews now skip user-level configuration, so a model or effort level, or a sign-in setting such as a custom model provider or an API-key helper, kept there no longer applies to them. Set the model in cadence's config (`verifier.model`, `codeReview.model` and the other seams' `model` keys), or set `verification.hostCliIsolation` to `"off"`.
