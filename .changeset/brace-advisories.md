Security housekeeping: pin `brace-expansion` past its two high advisories, and time-box an exception for the unpatched `braces` advisory. The required `security-success` check started failing on PRs to `main` independent of their changes. `main`'s last `Security` run (2026-09-28) was green. Dependabot PR #545 (2026-10-02), whose dependency tree is `main`'s, then failed on two unlisted high advisories, `GHSA-qhr7-859c-m2p7` / `GHSA-6j4f-fj2g-mc7p` (`brace-expansion`, published 2026-09-29). By PR #546 (2026-10-04) the audit also reported `GHSA-vfj7-8cjw-p6xm` (`braces`, published 2026-09-18). All three advisories are denial-of-service bugs in dev-only tooling: `pnpm why braces -r --prod` and `pnpm why brace-expansion -r --prod` are both empty, so no published CADENCE package ships either one.

The `pnpm.overrides` entry for the `brace-expansion` 5.x line had gone stale. `"brace-expansion@5.0.6": "^5.0.9"` was keyed on an exact version; once the tree moved to `5.0.9` that key matched nothing, the same silent no-op phase 297 fixed for `fast-uri`. And `5.0.9` is itself still vulnerable: `GHSA-6j4f-fj2g-mc7p` is fixed in `5.0.10` and `GHSA-qhr7-859c-m2p7` only in `5.0.11`. The entry is now the range key `"brace-expansion@^5.0.0": "^5.0.11"`, which resolves `brace-expansion@5.0.12` under the eslint / typescript-eslint toolchain's `minimatch@10.2.6` and keeps binding every 5.x dependent across future bumps instead of rotting on the next one. The `brace-expansion@^2.0.0` override is unchanged. Neither `brace-expansion` advisory gets an exception row: it is fixed, not tolerated.

`braces` has **no patched release** (vulnerable `<= 3.0.3`, no first patched version), so it cannot be fixed by an override. It reaches the tree only through `@changesets/cli` 2.x: several `@changesets/*` packages (directly, and via `@manypkg/get-packages` → `globby@11` → `fast-glob`) all end at `micromatch@4.0.8` → `braces@3.0.3`. `docs/security/audit-exceptions.md` gains one operator-approved row for `GHSA-vfj7-8cjw-p6xm` with a firm expiry of 2026-11-18 and a named unblock condition: a patched `braces` release, or adopting `@changesets/cli` 3.x (Dependabot #474), which drops `braces` from the tree. A major bump of the release tooling right before a release was deliberately not taken. The expiry is the gate — when it lapses, the advisory fails the audit job again rather than being quietly carried forward.

A new doc test drives `scripts/check-audit-exceptions.mjs`'s own `decideAdvisories` over the real exceptions table: before the expiry it accepts the `braces` advisory and still fails both `brace-expansion` advisories, and after the expiry it fails all three. The lockfile current-state test now pins the `^5.0.0` range key, asserts the retired `5.0.6` key is gone, and checks every resolved 5.x instance against the `5.0.11` floor. A stale doc comment in `scripts/check-lockfile-overrides.mjs` that still named the retired key is corrected.
