New read-only command `cadence assurance report` (phase 327, rec-20261010-002) rolls every `.cadence/phases/**/*-SUMMARY.json` up into one picture of how strongly your settled slices were verified. Each readable settled record is counted in one of three named categories, with the phase range each spans: un-gradable (no gate provenance), gradable but never graded (gate provenance but no `assurance` block) and graded. A settle that a gate refused and a file that cannot be read or parsed are reported as their own categories, by id or path, and an unreadable file never fails the command. For graded records the report shows the stored grade distribution, the distribution re-derived under the current assurance rule, and every record whose grade differs; it never rewrites a SUMMARY. It also gives per-gate ran / skipped / not-recorded counts, the provider-selection mix, the number of records with gate bypasses and the stored evidence tally. `--json` prints the report object (carrying a `schemaVersion`) that the text is derived from, and `--since <phase>` counts only records at or after that phase number; a `--since` value that is not a non-negative integer exits 1.
