`cadence doctor` and `cadence onboard` no longer report a `host-cli` verifier as ready when its binary is not installed (phase 337, rec-20261027-001). Previously readiness for `host-cli` was decided from config alone, so both commands said deep-verify was ready while `CADENCE_HOST_CLI_BIN` (or the default `claude`) could not be found, and every host-cli review then fell back to mock at settle. Readiness now looks the binary up the way the review spawn will (on `PATH`, or at the configured path; on Windows through the same `.exe`/npm `.cmd` shim resolution). When it is missing, `cadence doctor`'s `verification-readiness` check warns, naming the binary and every `host-cli` seam that will fall back to mock, with the fix: install it, point `CADENCE_HOST_CLI_BIN` at it, or switch those seams' provider. `cadence onboard` reports deep-verify as not ready when deep-verify uses `host-cli`, and its `--json` `verifier` payload gains `seamsUnresolvable`. When the binary is found, the readiness reason names it and says its login and the self-invocation guard are checked only when a review runs, instead of "credentials present". Readiness never spawns the binary; `cadence activate` and the review spawn path are unchanged.
